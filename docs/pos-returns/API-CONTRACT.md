# Addendum 39 — API contract

Conventions as A38 ([../pos/API-CONTRACT.md](../pos/API-CONTRACT.md)): ApiResponse, camelCase, UUIDs in routes, codes as strings, 2dp money, all `api/pos/*` gated by MODULE_POS. Decisions: [ADDENDUM-39-ANALYSIS.md](ADDENDUM-39-ANALYSIS.md).

## 0. Codes
- Reason `appliesTo`: `BOTH RETURN EXCHANGE`. Seeded reasons (D-4): DEFECTIVE, WRONG_ITEM, WRONG_SIZE, NOT_AS_EXPECTED (note), CHANGED_MIND, DUPLICATE, PRICE_MATCH (note+manager), WARRANTY (note+manager), OTHER (note).
- Order `orderType` gains `EXCHANGE`. Refund `method`: `CASH CARD MOBILE BANK_TRANSFER CHEQUE ON_ACCOUNT STORE_CREDIT` (ORIGINAL = the client picks the original tender's method). Payment method gains `STORE_CREDIT`.
- Store credit `status`: `ACTIVE FULLY_REDEEMED EXPIRED CANCELLED`; transaction `type`: `ISSUE REDEEM EXPIRE CANCEL ADJUST`.
- New order flags: `CROSS_STORE`, `AUTHORIZED_OFFLINE`, `AUTHORIZATION_INVALID`, `POLICY_OVERRIDDEN_OFFLINE`.
- Errors (exact): `"Cannot return a voided order."` · `"All items in this order have already been returned."` · `"Only sales can be returned."` · `"Return window expired ({n} days)."` (+ `requiresManager: true` in `result`) · `"Cannot return {q} of '{name}'. Only {r} returnable."` · `"A note is required for this reason."` · `"Manager authorization required."` (+ `result.requiresManager: true, result.reasons[]`) · `"This store does not accept returns from other locations."` · `"Cross-store returns require internet connectivity."` · `"No return policy configured. Contact your administrator."` · `"Exchanges are not allowed under this store's policy."` · `"This credit note has expired."` · `"Credit note redemption requires internet connectivity."` · `"This credit note belongs to another customer."` · `"Refund method not allowed by the store's return policy."`.

|---|---|---|
| `GET api/pos/return-reasons?appliesTo&includeInactive` | POS_ORDER_RETURN or POS_RETURN_REASON_MANAGE | `ReturnReason[]` (sortOrder) |
| `POST api/pos/return-reasons` | POS_RETURN_REASON_MANAGE | `ReturnReasonUpsert` → `ReturnReason` |

| `PATCH api/pos/return-reasons/{uuid}/status` | POS_RETURN_REASON_MANAGE | `{ isActive }` |
| `GET api/pos/stores/{uuid}/return-policy` | POS_STORE_VIEW or POS_ORDER_RETURN | `EffectivePolicy` |
| `PUT api/pos/stores/{uuid}/return-policy` | POS_RETURN_POLICY_MANAGE | `ReturnPolicyUpsert + rowVersion?` → `ReturnPolicy` |
| `DELETE api/pos/stores/{uuid}/return-policy` | POS_RETURN_POLICY_MANAGE | removes the store override |
| `GET api/pos/return-policies` | POS_RETURN_POLICY_MANAGE | `ReturnPolicy[]` (org default first) |
| `PUT api/pos/return-policies/default` | POS_RETURN_POLICY_MANAGE | `ReturnPolicyUpsert + rowVersion?` → org default (spec POST #8 = upsert) |
```ts
ReturnReason { uuid; code; name; description?; requiresNote; requiresManager; appliesTo; restockingFeeOverride?: number|null; sortOrder; isActive; modifiedAt }
ReturnReasonUpsert = ReturnReason minus (uuid, modifiedAt)        // code ≤20 [A-Z0-9_], unique per org; name ≤100
ReturnPolicy { uuid; storeUuid?: string|null; storeName?; name; returnWindowDays?: number|null; exchangeWindowDays?: number|null;
  requireReceipt; allowNoReceiptExchange; allowCrossStoreReturn; crossStoreRequiresManager; restockingFeePct;
  maxReturnNoAuth?: number|null; refundToOriginalMethod; allowCashRefund; allowCreditNoteRefund; creditNoteExpiryDays?: number|null;
  isActive; rowVersion; modifiedAt }
ReturnPolicyUpsert = ReturnPolicy minus (uuid, storeUuid, storeName, rowVersion, modifiedAt)   // fee 0–100, days ≥ 0
EffectivePolicy extends ReturnPolicy { source: 'STORE' | 'ORG_DEFAULT' }
```

## 3. Authorization, return, exchange, sync
| Route | Permission | Body → Result |
|---|---|---|
| `POST api/pos/returns/authorize` | POS_ORDER_RETURN (caller = cashier) | `{ terminalUuid, originalOrderUuid, amount, managerUserId?, pin }` → `{ authorizationToken; managerUserId; managerName; expiresAt }` (manager = active staff of the store, SUPERVISOR, with POS_RETURN_OVERRIDE — or POS_RETURN_CROSS_STORE when only cross-store needs it; shares the terminal PIN lockout) |
| `POST api/pos/orders/{uuid}/return` | POS_ORDER_RETURN + FEATURE_POS_RETURNS | `ReturnRequest` → `PosOrder` (RETURN) |
| `POST api/pos/orders/{uuid}/exchange` | POS_ORDER_RETURN + FEATURE_POS_RETURNS | `ExchangeRequest` → `PosOrder` (EXCHANGE) |
| `POST api/pos/returns/sync` | POS_ORDER_RETURN | `ReturnRequest|ExchangeRequest` with `kind: 'RETURN'|'EXCHANGE'`, `originalOrderUuid`, `createdAtLocal`, `isOffline`, `authorizedByUserId?` → `SyncResult` (A38 shape; idempotent on localId) |
```ts
ReturnRequest { localId; terminalUuid; shiftUuid; sessionUuid?; reasonUuid; note?; authorizationToken?;
  lines: { originalLineUuid; quantity }[]; refundMethod: string; refundReference?: string;
  storeCreditCustomerUuid?: string|null /* default: original customer unless walk-in → bearer */ }
ExchangeRequest extends ReturnRequest { newLines: SyncOrder['lines']; orderDiscountType; orderDiscountValue;
  payments: SyncOrder['payments'] /* for net > 0; may include STORE_CREDIT { creditNoteUuid } */ }
PosOrder (A38) gains: returnReasonUuid?; returnReasonName?; authorizedByName?; authorizedAt?; restockingFeeAmount; isCrossStore;
  originalStoreName?; storeCredit?: { uuid; number; amount; balance; expiresAt? }; netAmount? /* exchange */; settlement?: 'PAY'|'EVEN'|'REFUND'
PosPayment (A38) gains: creditNoteUuid?
```
Server rules: §0 errors; window from the **original** store's effective policy (POS-XST-06), acceptance from the processing store; restocking fee per D-5 (`restockingFeeAmount`, refund = return total − fee, remainder rule per line before the fee); manager needed when reason.requiresManager, refund > maxReturnNoAuth, window expired, or cross-store with crossStoreRequiresManager (`result.reasons`: `REASON`, `AMOUNT`, `WINDOW`, `CROSS_STORE`); refund methods: `refundToOriginalMethod` ⇒ must equal the original's largest non-cash tender method (else CASH), `allowCashRefund`, `allowCreditNoteRefund` (+ FEATURE_POS_CREDIT_NOTES) — ON_ACCOUNT only for credit sales (A38); STORE_CREDIT issues a store credit note (bearer when walk-in) with expiry from the policy. Exchange net = new total − (return total − fee) (D-6); net > 0 → payments must cover it; net < 0 → refundMethod covers |net|; net = 0 → no payment. Exchange respects the exchange window (0 = not allowed).

## Details fixed by the backend (POSR)
Decisions D-17..D-27 in the analysis doc. What the frontends see:
- **Errors with a result.** Manager needs answer 400 `{ success:false, message, result: { requiresManager: true, reasons: ["REASON"|"AMOUNT"|"WINDOW"|"CROSS_STORE", …] } }` (reasons in that order). Messages: no token ⇒ `"Return window expired ({n} days)."` if WINDOW is a reason, else `"Manager authorization required."`; `"The manager authorization is invalid or has expired."` (unknown, used, expired, other order); `"The refund exceeds the amount the manager authorized."`; `"This manager cannot authorize this return."`. Send `authorize.amount` = the refund value (return total − restocking fee) and `reasons` from the refusal; `reasons: ["CROSS_STORE"]` alone lets a POS_RETURN_CROSS_STORE supervisor authorize.
- **Authorize** 400s: PIN texts as the A38 PIN sign-in (`"PIN must be 4 to 6 digits."`, `"Invalid PIN."` (counts toward the terminal lockout), `"Terminal locked until HH:mm."`), `"This manager is not a supervisor of this store."` (managerUserId given), `"This manager cannot authorize returns."`, `"The user is inactive."`, `"The terminal is inactive."`; the caller must be staff of the terminal's store (403). `managerUserId` omitted ⇒ the PIN identifies one SUPERVISOR staff member of the terminal's store. Token: opaque base64url string, 5 minutes, single use.
- **ReturnRequest.** Processing shift = `shiftUuid` ?? the OPEN shift of `terminalUuid` ?? the OPEN shift of the original terminal (`"Open a shift on the terminal to refund this return."`). Send `terminalUuid` from the PWA (needed for cross-store). `reasonUuid` must be active and allow the kind (`"The reason '{name}' cannot be used for a return|an exchange."`); `note` ≤ 400 chars, `returnReason` stored as `"{name}: {note}"`. `refundMethod` required when something is refunded (`"Choose a refund method."` / exchange: `"Choose how to refund the difference."`). The A38 body (`reason` + `refunds[]`) is still accepted for returns. `storeCreditCustomerUuid` must be a known customer.
- **Window days** are store-local dates in the ORIGINAL store's timezone (offline: from `createdAtLocal`); expired when `daysSincePurchase > window`; null window = no limit. Fee, `maxReturnNoAuth`, refund-method rules, cross-store acceptance and store-credit expiry come from the PROCESSING store's policy. Lookup `policy` = processing store's EffectivePolicy with `returnWindowDays`/`exchangeWindowDays` taken from the original store; `withinExchangeWindow` is false when the processing store allows no exchanges; `crossStoreAllowed` = processing policy `allowCrossStoreReturn` and FEATURE_POS_CROSS_STORE_RETURNS. Lookup `receipt` matches `orderNumber` or `offlineNumber` (case-insensitive); `order.payments` are net of change.
- **Restocking fee** = round(Σ returned line totals × fee% / 100, 2, away from zero) — e.g. 11.70 at 15 % ⇒ 1.76, refund 9.94. RETURN `grandTotal` = refund; line amounts stay unscaled (remainder rule unchanged); `restockingFeeAmount` on the order.
- **Exchange** (`EXC-{store}-{yyyyMMdd}-{seq}`): lines = returned lines with negative quantity/amounts (carrying `originalLineUuid`) + new lines; `grandTotal` = new total − returned total; `netAmount` = grandTotal + fee; `settlement` PAY/EVEN/REFUND; `paymentStatus` REFUNDED when net < 0. Payments: an `EXCHANGE` refund and an `EXCHANGE` tender of min(return value, new total), then the refund (net < 0) or the client's `payments` (net > 0; exact A38 tender rules against `netAmount`; `"Payments must cover the difference (X)."`). Net ≤ 0 with payments ⇒ `"No payment is taken when the new items do not cost more."`. New-line discounts need POS_ORDER_DISCOUNT. Exchanges cannot be voided.
- **Store credit refund**: `storeCredit { uuid, number, amount, balance, expiresAt }` on the RETURN/EXCHANGE; the refund payment has `method: STORE_CREDIT`, `reference` = the CN number, `creditNoteUuid`. Walk-in ⇒ bearer note. Offline issue: send `storeCreditOfflineNumber` (`CN-{store}-OFF-…`) in `returns/sync`; the server number replaces it and `GET credit-notes/lookup?number=` finds either.
- **Redemption** (`payments[].method STORE_CREDIT` + `creditNoteUuid`, sale sync or exchange): needs POS_CREDIT_NOTE_REDEEM (403) and FEATURE_POS_CREDIT_NOTES; 400s `"Credit note redemption requires internet connectivity."` (any order pushed with `isOffline:true`), `"This credit note has expired."`, `"This credit note belongs to another customer."`, `"This credit note was cancelled."`, `"This credit note has no balance left."`, `"The credit note {number} has only X left."`, `"A store credit payment needs the credit note."`, and the A38 tender text when it exceeds the order's open balance. Concurrent spend ⇒ 409 `"The credit note was used at the same time. Check its balance and try again."`. `config.paymentMethods` lists STORE_CREDIT only while FEATURE_POS_CREDIT_NOTES is on; `config.features` gains `creditNotes`, `crossStoreReturns`.
- **StoreCredit DTO**: `status` reads EXPIRED for an ACTIVE note past `expiresAt` (refused too) even before the nightly job; `redeemedAmount` = net of void restores; also `offlineNumber`. `currencyCode` = org sale base (may be null). List `status` takes a comma list, `search` = number / offline number / customer name, newest first. `POST credit-notes`: amount > 0 (2dp), `expiresAt` future or omitted (⇒ the store's policy days), `localId` idempotent; `cancel` only ACTIVE (`"Only an active credit note can be cancelled."`). Customer list ≤ 200 newest. Voiding a sale paid by store credit puts the amount back (ADJUST transaction, ACTIVE again).
- **QA additions (2026-10-11)**: return/exchange/sync bodies also take `cashierUserId` (honoured when active staff of the processing store with POS_ORDER_RETURN, else booked to the caller + warning) and `sessionLocalId` (that device session of the shift; offline fallback = the cashier's latest session). An offline `returns/sync` while FEATURE_POS_RETURNS reads off (also during MODULE_POS grace) is accepted with the warning `"Returns are not enabled for your organization."`; online it is still refused. `sync/return-reasons` `nextSince`/`modifiedAt` are UTC (`Z`).
- **returns/sync**: `kind` RETURN (default) or EXCHANGE; result = A38 SyncResult (`flags`, `warnings`). Offline (`isOffline:true`) policy breaches are accepted with `POLICY_OVERRIDDEN_OFFLINE` + the refusal text as a warning; `authorizedByUserId` ⇒ `AUTHORIZED_OFFLINE` (+ `AUTHORIZATION_INVALID` if that user is not an active SUPERVISOR staff member of the store with the needed permission). Cross-store and redemption are refused offline. Replaying a `localId` of the same kind and original answers the stored order; otherwise 409.
- **Reasons/policies**: reason `code` upper-cased, `[A-Z0-9_]{1,20}`, unique (`"Reason code {code} already exists."`); `appliesTo` filter on GET returns BOTH + that kind. Policy upsert: name ≤ 100 (empty ⇒ a default name), days ≥ 0, fee 0–100 (2dp), `maxReturnNoAuth` ≥ 0; `rowVersion` mismatch ⇒ 409. `DELETE stores/{uuid}/return-policy` is idempotent. `sync/return-reasons` includes inactive reasons; `nextSince` = latest `modifiedAt` sent (or `since`).
- **Shift**: `totalStoreCreditIssued` = STORE_CREDIT refunds on the shift (standalone issues are on no shift); STORE_CREDIT/EXCHANGE refunds are not in `totalOtherRefunds`; exchanges count in `orderCount` and `refundCount`; `grossTotal` gets an exchange's new part, `netTotal` loses its return part after the fee. Session totals count exchange tenders as sales.
- **Hub**: `ReturnProcessed.refundMethod` = the refund method, `EXCHANGE` when nothing was paid out, `MIXED` for an A38 multi-tender refund; `refundAmount` = what was paid out. `ReturnPolicyChanged` goes to the store (store override) or to every active store (org default). Notifications: `POS_CROSS_STORE_REPORT` weekly to POS_RETURN_REPORTS holders.

The feature is not checked by the route guard (none exists); the list page shows a "switched off" note and hides Issue instead.
- **Store Returns tab** (read: POS_STORE_VIEW, write: POS_RETURN_POLICY_MANAGE). `source: ORG_DEFAULT` ⇒ "Use organization default" (read-only values). Switching to "store-specific" pre-fills the org default's values (name "{store} return policy") and PUTs without `rowVersion`; an existing store policy is PUT with its `rowVersion`. - **Org policy page** reads `GET return-policies` (default = the entry with no `storeUuid`; none yet ⇒ recommended values, the PUT creates it) and lists the store overrides with links.
- **Reasons page** sends `includeInactive=true`. Reorder = two `PUT`s swapping `sortOrder` with the neighbour (equal orders are separated by 1). New reasons get max sortOrder + 10. Codes are upper-cased with spaces → `_` as they are typed.
- **Back-office return** (`POST orders/{uuid}/return`): sends the A39 body (`reasonUuid`, `note` ≤ 400, `refundMethod`, `refundReference`, `shiftUuid` + that shift's `terminalUuid`) **and** the A38 fields (`reason` = "{name}: {note}", `refunds: [{ method, amount: refund after fee, reference }]`); per POSR, `refundMethod` wins. No `authorizationToken`: a back-office user records an override return only by holding POS_RETURN_OVERRIDE. Before sending, the dialog shows a hint of what needs a manager (reason, refund > `maxReturnNoAuth`, window passed by local days since `createdAtLocal`); when the server answers `result.requiresManager`, its message is shown verbatim with `result.reasons` in words. Reasons list = active, `appliesTo` RETURN/BOTH; if it cannot be loaded, the A38 free-text reason is asked. Refund methods follow the store's effective policy like POSR's check (cash only if allowed, ON_ACCOUNT only for credit sales, STORE_CREDIT only with `allowCreditNoteRefund` + the feature, `refundToOriginalMethod` ⇒ only the original method = largest non-cash method by Σ(amount − change)); no allowed method ⇒ the dialog says so. Fee preview = round(return total × (reason override ?? policy %) / 100, away from zero); refund = total − fee. `storeCreditCustomerUuid` is not sent (server default: original customer, walk-in ⇒ bearer). The back office does not create exchanges.

Order list: type filter gains Exchanges; `CROSS_STORE` etc. are flag pills.
- **Store credit pages**: status `FULLY_REDEEMED` is shown as "Used up"; holder "Bearer" when there is no customer; active credit expiring within 30 days is highlighted. Transactions oldest first; `REDEEM` = "Spent", `ADJUST` = "Restored (sale voided)". Detail transactions come from the detail's `transactions`, or `GET …/transactions` when that is missing. Cancel (ACTIVE only) sends the optional note. The issue dialog sends `localId`; a blank expiry is omitted (the store's policy decides).
- **Shift**: "Store credit issued / redeemed" tiles appear when the shift carries the two totals. **Customer page**: "Store credit" section (MODULE_POS + FEATURE_POS_CREDIT_NOTES + POS_CREDIT_NOTE_VIEW) lists `GET customers/{uuid}/credit-notes` with the total of active balances.

## Details fixed by the frontend (FEPOS)
PWA in `SupplyChainFrontend/src/app/pos/*`. Rules: `core/pos-return-rules.ts`; flow and submission: `core/pos-return-flow.service.ts`.
- **Dexie v2** adds `returnReasons` (uuid, code, sortOrder), `storeCredits` (uuid, number, customerUuid, status) and `returns` (the return/exchange queue: localId, syncStatus, createdAtLocal, shiftUuid, originalOrderUuid, originalOrderLocalId). It only adds tables, so every v1 table and row is kept (asserted in `pos-db.spec.ts`). Unbind wipes reasons, the store-credit cache, the cached policy and synced returns. Queued or failed returns count in the queue badge and block Unbind. They are listed under `/pos/settings` with Retry.
- **Pulls.** After config, `sync/return-reasons` (delta on `since`, cursor `nextSince ?? serverTime`; full sync replaces the table) and `sync/return-policy` (cached in Dexie config). A refusal is logged and keeps the device data, except `"No return policy configured…"`, which clears the cached policy. `ConfigChanged` and `ReturnPolicyChanged` (this store, or no `storeUuid`) pull both again. Store credits are fetched on demand: the customer's ACTIVE notes and lookup by number. The device keeps them as a display-only cache, and the Dexie copy is never used to accept a tender. `CreditNoteIssued`/`Redeemed`/`Expired` update that cache. `ReturnProcessed` refreshes the history.
- **Features.** `config.features.creditNotes` / `crossStoreReturns` when present, otherwise the cached `tenant/modules/enabled` codes (unknown ⇒ on). `config.paymentMethods` drops STORE_CREDIT/EXCHANGE: the payment screen offers STORE_CREDIT itself, only with the credit-notes feature and POS_CREDIT_NOTE_REDEEM. Routes `/pos/return*` and `/pos/exchange/*` need an OPEN shift, `features.returns` and POS_ORDER_RETURN.
- **Lookup.** The receipt number is scanned (keyboard wedge into the field) or typed. Online: `orders/lookup` with the terminal's store. If the server does not know the receipt (`found:false`/404/401/network), the PWA falls back to a sale on this device (matched by `orderNumber`, `offlineNumber` or localId). Offline: device sales only. A receipt whose `POS-|RET-|EXC-{code}-` is another store's ⇒ `"Cross-store returns require internet connectivity."`. Other unknown receipts ⇒ "not on this device". Customer search: device customers, then the customer's synced sales via `GET orders?search={code}&orderType=SALE` (POS_ORDER_VIEW) plus device sales. "Recent sales" = the newest 20 sales of this device. Route key = server uuid, or `local-{localId}` for a sale the server has not got yet. History's Return/Exchange buttons open `/pos/return/{uuid}` (`?mode=EXCHANGE`).
- **Device sale as returnable order (offline).** Lines come from the stored payload and receipt. Returned qty and amounts come from this device's earlier returns of that sale (failed ones excluded). `refundIfAllReturned` = lineTotal − Σ those amounts. Days = full days since `createdAtLocal` (device clock; the server re-judges by store-local date). Window: within = `days ≤ window` (null = no limit); exchange window = `exchangeWindowDays ?? returnWindowDays`, 0 = no exchanges.
- **Amounts.** Line share = A38 remainder rule using `refundIfAllReturned`. Fee = round(Σ shares × pct / 100, 2, away from zero), computed on integers (POSR's 11.70 @ 15 % ⇒ 1.76 is asserted). The reason's `restockingFeeOverride` wins over the policy, and 0 waives the fee. Refund = Σ − fee. Exchange new items: §1 calculator with the store's tax and no discounts (the exchange cart has no discount UI). Net = new total − refund → PAY / EVEN / REFUND.
- **Manager.** The client asks before submitting when the reason requires a manager, refund > `maxReturnNoAuth`, the window (exchange window for exchanges) expired, or the sale is cross-store and `requiresManagerForCrossStore`. It also asks after any 400 carrying `result.requiresManager` (reasons from the result; none ⇒ WINDOW), and after `"The manager authorization is invalid or has expired."` / `"The refund exceeds the amount the manager authorized."`. Authorize amount = refund (return value before netting, also for exchanges). An authorization stays valid while the amount ≤ its ceiling and before `expiresAt`. Online (server order): `returns/authorize` without `managerUserId`, and the token goes on the return/exchange. Offline, or for a device-only sale: the PIN is checked against the cached hashes and shares the device's 5-wrong-PIN lock. The manager must be SUPERVISOR with POS_RETURN_OVERRIDE, or POS_RETURN_CROSS_STORE when CROSS_STORE is the only reason. The request then carries `authorizedByUserId` and no token.
- **Refund methods.** `refundToOriginalMethod` ⇒ only the original's largest non-cash tender (net of change; else CASH). That method is dropped when it is CASH and `allowCashRefund` is off, or when it is STORE_CREDIT. Otherwise the terminal's methods: CASH only with `allowCashRefund`, ON_ACCOUNT only when the sale had ON_ACCOUNT. STORE_CREDIT is added with `allowCreditNoteRefund` and the feature. If none remain, the screen shows `"Refund method not allowed by the store's return policy."`. Default = the original method when allowed. Refund references are optional for CARD/MOBILE/BANK_TRANSFER/CHEQUE. When nothing is refunded (exchange PAY/EVEN), `refundMethod` still carries the first allowed method. `storeCreditCustomerUuid` = the original customer, or null for walk-in (bearer). Note ≤ 400.
- **Submission.** Every return/exchange is written to Dexie `returns` first, with a stable `localId` per flow. Online with a server order: `POST orders/{uuid}/return|exchange` is awaited, and the answer (number, flags, fee, authorizer, `storeCredit`) is stored as `synced`. A rule refusal (4xx except 401) drops the record and shows the server text. With no answer (network/5xx/401): cross-store ⇒ dropped with the cross-store message; otherwise the record is queued as an offline return (`isOffline:true`, `authorizedByUserId` kept). An exchange paying with STORE_CREDIT stays an online request (`isOffline:false`) and is replayed with the same localId. Offline, or with a device-only sale: queued for `returns/sync` with `kind`, `createdAtLocal`, `isOffline:true`, `authorizedByUserId`, plus the A38 extras `cashierUserId`, `sessionLocalId` and `sessionUuid` (filled at push). When the refund is store credit, it also carries `storeCreditOfflineNumber` = `CN-{store}-OFF-{first 8 hex of localId}`, the number printed on the offline receipt.
- **Queue push** runs after sessions, cash movements and sales, in `createdAtLocal` order, one at a time. If the original sale is still queued, the return waits. If the sale was refused, the return is marked error. Lines that only know the device's `localLineId` are resolved with `GET orders/{uuid}` (cashier-else-device token): the same `lineNumber` and variant, else the only line of that variant. Success ⇒ synced with flags and warnings. When store credit was issued, the return order is read once to replace the offline CN number with the server's. Backoff and error handling are as for sales.
- **Store credit tender.** Online only, offered by number (typed or scanned, `credit-notes/lookup`) or from the customer's ACTIVE list (`customers/{uuid}/credit-notes`). Refused on the till with the server wording: expired (or past `expiresAt`), cancelled, no balance, another customer's note. Amount ≤ min(balance − already tendered on that note, remaining due), prefilled with that cap, no change. Tender `reference` = CN number, `creditNoteUuid` sent. A sale with STORE_CREDIT is refused offline before saving. If the server cannot be reached during the push, the sale stays queued with `isOffline:false` (replayed, never turned offline). Exchange payments omit ON_ACCOUNT.
- **Screens.** `/pos/return` (lookup), `/pos/return/:key` (lines with ± / All, reason buttons, note, live summary, window pill, manager banner, Return/Exchange toggle), `/pos/return/:key/refund` (also the REFUND settlement of an exchange), `/pos/exchange/:key` (the selling grid, now the shared `PosProductGridComponent`, plus a cart with RETURNING negative lines and fee, NEW ITEMS and net), `/pos/payment?exchange={key}` (the existing payment screen paying the net), `/pos/return-receipt/:localId` (print), `/pos/credit-note/:uuid` (`:uuid` = server uuid or the issuing return's localId; server balance with POS_CREDIT_NOTE_VIEW, else the device data). The CN number is a Code 128 B barcode drawn as inline SVG by an in-house encoder (`core/pos-code128.ts`, no dependency), black on white also in dark mode. A reload in the middle of the flow returns to the items step.
- **History**: All / Sales / Returns / Exchanges (`orderType` param, also filtered client-side), Return/Exchange badges, the device's unsynced returns, detail rows for reason, fee, authorizer, settlement, cross-store and a store-credit link. The A38 return dialog is replaced by the A39 flow. **Shift**: "Store credit issued / redeemed" tiles when the shift carries the totals.
