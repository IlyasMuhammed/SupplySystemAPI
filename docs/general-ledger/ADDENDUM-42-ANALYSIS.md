# Addendum 42 — Chart of Accounts, Fiscal Periods, GL Opening Balances, Integration Hooks: analysis & decisions

Source: SMS-FSD-ADD-042 v1.0 + task register (A42-0001..0643), received 2026-10-13. Contract: [API-CONTRACT.md](API-CONTRACT.md). Status: [ADDENDUM-42-TASKS.md](ADDENDUM-42-TASKS.md).
User said "work for the addendum 42" / "start multiple agents" → recommended defaults adopted (standing rule).

## Part A — spec vs. this repo

| Spec says | Reality here | Consequence |
|---|---|---|
| React 18 | Angular 19 + PrimeNG, SMS Flow `sf-*` kit | All UI tasks are Angular components (D-26) |
| `org_id int`, int ids in routes | `Guid OrganizationId` (ITenantScopedEntity), int Id + Guid Uuid, UUIDs in routes | D-1 |
| `core.ModuleCatalog`, `FINANCE` module to activate | A37 registry: MODULE_FINANCE already exists and is on for orgs that have it | No new module; GL is a sub-feature (D-3) |
| Create `finance` schema | Schema `finance` already exists (Finance module: invoices, payments, tax codes, ledgers) | M1 is a no-op guard |
| "Before this addendum SMS has no financial backbone" | Sub-ledgers exist (sales/supplier invoices, payments, credit notes, customer/supplier/product ledgers); **QuickBooks is the GL** for orgs that use it | GL here is new and optional; nothing existing posts to it in A42 |
| Gate on **all** `/api/finance/*` until setup Complete | `/api/finance/invoices`, `/payments`, `/tax-codes`, `/master-ledger`, `/opening-balance-date` … are live for every org | Gating them would lock every org out of invoicing → D-4 |
| Journal entries (type OPENING_BALANCE) | No journal engine (deferred to A43) | Minimal `JournalEntries/Lines` for opening balance only (D-10) |
| Conversion date | A40 already has the org's **opening balance date** (Finance `org_settings`) with the same meaning | One date, D-11 |
| Domain events | Module-local publisher pattern (A41 `ICrmEventPublisher`) | D-20 |
| `Finance.Admin` / `Finance.Write` roles | Permission codes + role grants | D-14 |
| FK to lookups.Countries/Currencies | Cross-module refs are unenforced scalars | D-7 |

## Decisions (adopted)

- **D-1 Conventions.** int `Id` + `Guid Uuid`, `Guid OrganizationId`, PascalCase columns, UUIDs in routes, ApiResponse envelope, camelCase JSON, codes as strings. Spec field names keep their meaning (snake_case only in CSV/JSON files).
- **D-2 Module.** New project `SMS.Modules.Accounting` (references only SMS.Shared), own `AccountingDbContext`, tables in schema `finance` with the spec's names (`CoaTemplates`, `CoaTemplateItems`, `ChartOfAccounts`, `FiscalYears`, `FiscalPeriods`, `AccountingDefaults`, `CoaSetupStatuses`, `OpeningBalanceEntries`, `ExternalSystemMappings`, plus `JournalEntries`, `JournalEntryLines`, `GlSetupHistory`). One guarded/idempotent migration `A42_AccountingInitial` (every CREATE behind IF NOT EXISTS — the API migrates SMSGlobal at startup).
- **D-3 Feature.** `FEATURE_GENERAL_LEDGER`, sub-feature of MODULE_FINANCE, on all plans that include Finance; existing orgs follow their plan. Nothing posts to the GL in A42, so turning it on changes nothing until a user opens the wizard.
- **D-4 Gate (deviation).** The setup gate is an action filter `[RequiresGlSetup]` (403 `{ error: "FINANCE_SETUP_REQUIRED", message, currentStatus, redirectUrl }`), applied **only** to post-setup GL endpoints (A42: `GET api/finance/gl/dashboard`; A43: journals/postings). Existing finance endpoints are **not** gated. All A42 setup endpoints (templates, CoA, fiscal, defaults, opening balances, setup, mappings) are setup endpoints. Angular route guard: GL dashboard → wizard when not Complete, with a banner naming the next step.
- **D-5 Templates.** All 16 template headers seeded. Account items authored (embedded JSON) for **GLOBAL_GENERAL (~65), US_GENERAL (~70) and PK_GENERAL (~65)** — PK added because tenants run in PKR. The other 13 list with `accountCount = 0` and Apply disabled ("Accounts for this template are coming"). Tenant custom templates: the `OrganizationId` column and visibility rule exist (system + own), no authoring UI in A42.
- **D-6 Seeding.** Idempotent startup seeder (not migration data): upserts headers by `TemplateCode`, replaces a template's items only when its JSON `version` differs, refreshes `AccountCount`.
- **D-7 Country/currency.** Stored as codes (alpha-3 country, ISO 4217 currency), no cross-module FK.
- **D-8 Codes.** Level 1 codes fixed `1`..`5` (Asset, Liability, Equity, Revenue, Expense). Every descendant's code must start with its root digit. Child-code-starts-with-parent-code is **auto-suggest only** (not enforced) so legacy uploads work. Codes `[A-Za-z0-9]{1,20}`.
- **D-9 System accounts.** The 5 roots and `3900 Opening Balance Equity` are `IsSystemAccount`. If 3900 is missing its parents are created: `39 Opening Balances` (L2) and `390 Opening Balance Equity` (L3), both Equity. System accounts can't be deleted, renamed (3900) or re-coded.
- **D-10 Journal (minimal).** `JournalEntries` (Uuid, number `JE-YYYY-NNNNN`, type, date, reference, status POSTED, totals) + `JournalEntryLines` (account, debit, credit, memo). A42 only ever writes type `OPENING_BALANCE`. "Posted journal entries exist" (R13, reset, BR-MG-004) = any JournalEntry of another type (none in A42) — the opening balance itself only blocks re-upload/apply after posting.
- **D-11 Conversion date = A40 opening balance date.** One date, owned by Finance (`api/finance/opening-balance-date`). GL posting requires it set and inside the first fiscal year. Once GL opening balances are posted the date is locked: Accounting implements new Shared `IOpeningDateLockSource` and Finance's date guard consults every registered source (A40 stock source generalised). `CoaSetupStatus.ConversionDate` is a copy taken at posting.
- **D-12 Sub-ledger reference (info only).** Step 5 shows, next to the default A/R, A/P and Inventory accounts, the A40 customer opening total, supplier opening total and posted opening-stock value (Finance seam `IOpeningSubledgerTotals`), with a "differs" warning. Never blocks.
- **D-13 Currency.** GL in the org's base currency (A35). Fiscal year reporting currency defaults to it.
- **D-14 Permissions.** `GL_VIEW` (read everything), `GL_ACCOUNT_MANAGE` (CoA create/update/delete = Finance.Write), `GL_SETUP_MANAGE` (apply/upload, fiscal years/periods, defaults, opening balances, complete/reset, mappings = Finance.Admin). Prefix `GL_` → MODULE_FINANCE in ModuleCodeMap. Grants by role code: roles holding FINANCE_SETUP_MANAGE (and org admin) get all three; roles holding INVOICE_VIEW or SALES_INVOICE_VIEW get GL_VIEW. Auditor gets GL_VIEW.
- **D-15 Lazy per-org init.** The `CoaSetupStatuses` row (NotStarted) and the 16 `AccountingDefaults` rows are created idempotently on first access by an org.
- **D-16 Status.** Stored status = furthest consecutive satisfied step (NotStarted → AccountsCreated → FiscalYearSet → DefaultsSet → BalancesEntered → Complete), recomputed after every setup action from the flags; never goes past a missing step. Apply/upload allowed only in NotStarted/AccountsCreated (BR-TPL-004) and before opening balances are posted. Account CRUD stays allowed before and after Complete (within rules). Complete → roots and conversion date locked.
- **D-17 Reset.** Allowed while no non-opening journal entries exist; deletes CoA, fiscal years/periods, default assignments (rows kept, AccountId null), opening entries, the opening journal and mappings; status NotStarted; date lock released.
- **D-18 Periods.** Lock/Close/Reopen per BR-FP-003/005; close blocked by Draft journal entries (none in A42); year close needs all periods Closed. Period dates editable via PUT while no postings, validated for gaps/overlaps across the year (covers 4-4-5/custom). Shared `IFiscalPeriodGuard.IsPostingAllowedAsync(org, date)` for A43.
- **D-19 Opening balances.** Leaf accounts only; not both sides; ≥ 0; **3900 cannot be entered manually** (it is the plug). Post: difference ≠ 0 requires `acknowledgeDifference: true` (else 400); plug line to 3900; journal + account opening/current balances + `HasTransactions`. **Skip** = post with no entries: entered = balanced = true, no journal. Revenue/Expense balances allowed with a warning.
- **D-20 Events.** `IAccountingEventPublisher` (A41 pattern) with the 12 Appendix B events, published after commit; every event also written to `GlSetupHistory` (shown on Setup Status page).
- **D-21 External mappings.** Table + CRUD + CSV import/export, 12 system types, directions None/Inbound/Outbound/Bidirectional, leaf+active only. `connectionConfigJson` refused if any key matches password|secret|token|apikey|api_key|clientsecret|client_secret|privatekey (BR-INT-005). No connectors. The existing QuickBooks integration keeps its own account settings unchanged.
- **D-22 Exports.** Template and tenant CoA export in the same CSV/JSON formats (spec §5.3/5.4, Appendix C); blank templates downloadable.
- **D-23 Account types.** Appendix A validity per root type enforced (Tax allowed on Asset and Liability); group accounts have no type.
- **D-24 Defaults.** Assigned account must be leaf, active, same org (hard). Expected account type mismatch = warning only. DEFAULT_OPENING_BALANCE auto-assigned to 3900 and locked.
- **D-25 Limits.** Max 2000 accounts per tenant and per upload; upload ≤ 5 MB.
- **D-26 Frontend.** Angular, SMS Flow kit. Menu Finance › "General Ledger" (feature FEATURE_GENERAL_LEDGER + GL_VIEW): Setup wizard `/portal/pages/finance/gl/setup`, Dashboard `/gl`, Chart of Accounts `/gl/accounts`, Fiscal Years `/gl/fiscal-years`, Defaults `/gl/defaults`, Opening Balances `/gl/opening-balances`, Integrations `/gl/integrations`, Setup Status `/gl/setup-status`. Contextual help per step.
- **D-27 Out of scope.** GL journal engine, AR/AP sub-ledger posting, bank rec, statements (A43 per spec); tenant template authoring UI; connectors.
- **D-28 (BE1) Draft opening entries may have no date.** `OpeningBalanceEntries.ConversionDate` is nullable (FSD: NOT NULL): drafts can be saved before the A40 opening balance date is set; the post stamps it on every entry and copies it to `CoaSetupStatuses.ConversionDate`.
- **D-29 (BE1) Journal vocabulary.** `JournalEntries.Status` uses `Draft`/`Posted` (PascalCase like period/entry statuses; CHECK), `EntryType` is an upper-case code (`OPENING_BALANCE`) with no CHECK so A43 can add types without a migration. Number `JE-YYYY-NNNNN` unique per org (`UX_JournalEntries_Org_Number`).
- **D-30 (BE1) Complete is terminal.** `ISetupStatusService.RecomputeAsync` derives NotStarted…BalancesEntered from the data and never demotes `Complete`; only `POST setup/reset` leaves it. Services that could break a prerequisite after completion (unassigning a required default, deactivating the last accounts) must refuse it themselves. `OpeningBalancesEntered/Balanced/PostedAt` are set by the opening balance post/skip (not derived).
- **D-31 (BE1) Gate body.** The `[RequiresGlSetup]` 403 body is the contract's `{ error: "FINANCE_SETUP_REQUIRED", message, currentStatus, redirectUrl }` plus the ApiResponse fields (`success: false`, `result: null`), so the Angular error interceptor reads it like any other failure.
- **D-32 (BE1) Complete refusal.** `POST setup/complete` with unmet prerequisites → 409 `ApiResponse.Fail(message, { unmet: string[] })`; messages: "Create the chart of accounts.", "Set up a fiscal year.", "Assign every required accounting default.", "Post or skip the opening balances.", "The opening balances must balance.". Already Complete → 200, no-op.
- **D-33 (BE1) Template visibility.** `CoaTemplate` implements Shared `IGloballyExemptTenantScopedEntity` (the LookupValue pattern): property `IsGlobal` → column `IsSystem`, `OrganizationId` nullable; filter = super admin OR system OR own org; a new non-system template is stamped with the caller's org. Template items have no org column and are always reached through their template.
- **D-34 (BE1) Schema details.** Migration history in the shared `dbo.__EFMigrationsHistory` (like every module). All in-module FKs are NO ACTION except template→items, fiscal year→periods, journal→lines (CASCADE); `SourceTemplateId`/`TemplateId` are NO ACTION (FSD: SET NULL) — templates are never hard-deleted. Extra columns: `Uuid` on every root entity (incl. AccountingDefaults), `CoaTemplates.SortOrder`, `AccountingDefaults.ExpectedAccountType/SortOrder` (`isLocked` is computed: DEFAULT_OPENING_BALANCE), `FiscalYears.ClosedAt/ClosedBy`, `CoaSetupStatuses.OpeningBalancesPostedAt/SetupCompletedByName`, `OpeningBalanceEntries.JournalEntryId`. `ModifiedAt` is non-null (app-stamped `IHasModifiedAt`, A37 D-16). Extra CHECKs: parent null iff level 1, account type vocabulary, default key only on default items, debit/credit ≥ 0 and not both > 0 (entries, lines, account opening), path starts with `/`, fiscal year end > start, period end ≥ start.
- **D-35 (BE1) GL grants.** `AuthDataSeeder.SeedGlGrantsAsync` (every start, only missing grants, a switched-off grant stays off): by role CODE — FINANCE_MANAGER all three, FINANCE_OFFICER and AUDITOR `GL_VIEW`; and by what any role (built-in or custom, any org) is *allowed* — FINANCE_SETUP_MANAGE → all three, INVOICE_VIEW or SALES_INVOICE_VIEW → `GL_VIEW`. System Admin / Org Admin through `PermissionCodes.All`. Role-editor group "General Ledger".
- **D-36 (BE1) Existing orgs follow their plan.** `FEATURE_GENERAL_LEDGER` is in `TenancyFeatureCatalog.PlanDefaultForExistingOrgs`: an existing org's new row is licensed = its plan's default (Standard/Enterprise yes, Basic no) and enabled = licensed AND Finance on. A Basic org whose Finance was licensed by hand does not get the GL automatically (super admin licenses it).
- **D-37 (BE1) Lazy init refreshes the catalog.** `IAccountingInitializer.EnsureAsync(org)` creates the status row and any missing of the 16 default rows, and refreshes label/category/required/expected type/help text/order of existing rows from `DefaultKeys.Definitions` — never the assigned account. Concurrency-safe (a lost insert race re-reads). Nothing is created at startup.
- **D-38 (BE1) Event payloads.** The 12 events are module-local (`Services/AccountingEvents.cs`), ids are uuids, and each carries `UserId`/`UserName` (null = system). Additions to Appendix B: names/codes for readable history, `CoaSetupStatusChangedEvent.Note` ("Setup reset"), `OpeningBalancePostedEvent.JournalEntryNumber/Skipped`. Every event is written to `GlSetupHistory` (immutable) by `GlSetupHistoryWriter`; reset is recorded as a status change with note "Setup reset".
- **D-39 (BE1) Template seeding rule.** `TemplateSeeder` (startup, after Migrate, best effort — logged, never stops the API) upserts the 16 system headers from embedded `templates.json` (order = file order) and replaces a template's items when the items file's `version` differs from the stored one **or** the template has no items yet while its file has some (so a file added later under the same version still seeds). Items files go through the upload validator first; an invalid file is logged and skipped (previous items kept). `AccountCount` = stored items (all levels).
- **D-45 (BE1) Upload errors.** 400 body = `{ success: false, message, errors: UploadError[], result: null }`; `UploadError` gains `path` (JSON node, e.g. `accounts[0].children[2]`) besides `line` (CSV, header = line 1) and `code`. Sorted by line/path then rule. Rule codes beyond the spec's literal list: D-8 "must start with the root digit", unknown `root_type`, D-23 type-vs-root and the 3900/39/390 reservations → **R9**; a type on a group → **R8**; bad `is_group` text → R7/R8; description > 500 → **R12**; unknown `default_account_key` → **R1**. R13 (posted journals) is a one-item 400 list on upload and a 409 on apply. File > 5 MB → plain 400 "The file must be 5 MB or smaller."; other extension → R1.
- **D-46 (BE1) File formats.** CSV: exact 8-column header (case-insensitive), RFC 4180 quoting (comma/quote/line break → quoted, quotes doubled), quoted fields may span lines, blank lines skipped, written UTF-8 **with BOM** + CRLF; `is_group` accepts true/false/1/0/yes/no. JSON: the §5.4 tree (children omitted on leaves; `is_default_account`/`default_account_key` written when set — template and tenant exports carry the default markers, so an export re-uploads with its defaults); a top-level node may give `parent_code`, so a flat list works too. Uploads honour default markers like Apply.
- **D-47 (BE1) Replacing the chart.** Apply/upload run RecomputeAsync, then are refused (409 "The chart can only be replaced…") unless status ∈ {NotStarted, AccountsCreated}, no fiscal year exists and opening balances are not posted. One transaction: the org's draft opening balances and mappings are deleted, default assignments cleared, all its accounts (incl. inactive) deleted, the new chart inserted (paths computed; roots + 3900 system; 39/390/3900 added when missing), defaults assigned from the rows' markers + DEFAULT_OPENING_BALANCE → 3900 (no per-default events; the applied/uploaded event covers it). `TemplateAppliedAt` is set on apply only. A template with 0 items → 409 "Accounts for this template are coming…".
- **D-48 (BE1) Account CRUD.** Create: parent must be an active group; level = parent + 1 and root type from the parent; code `[A-Za-z0-9]{1,20}` starting with the root digit, unique among active accounts; ≤ 2000 active accounts; sortOrder defaults to last sibling + 10. Update: name/type/description/externalCode/sortOrder; 3900 cannot be renamed or re-typed; roots can be renamed only before Complete. Soft delete is refused, in this order: system account, active children, has transactions, assigned to any default ("This account is assigned as {label}. Assign another account first." — before and after Complete), non-zero draft opening balance, external mapping. A zero draft opening row goes with the account; a deleted code can be reused.
- **D-49 (BE1) Extra read routes.** `GET chart-of-accounts?includeInactive=true` (tree default: active only), `GET /{uuid}/subtree` (materialized path LIKE, active, path order), `GET /{uuid}/ancestors` (root first; recursive CTE on SQL Server, parent walk elsewhere). `suggest-code` = parent code + first free digit 1–9, then 10–99. Templates: `countryCode=GLOBAL` (or `none`) = country-agnostic; search covers name, code and description; `/filters` country names from a built-in alpha-3 map. `DELETE api/finance/templates/{uuid}` (GL_SETUP_MANAGE) deactivates a custom template; a system one → 403 "System templates are read-only." (T-TPL-04).
- **D-60 (BE1) Manual start (FSD §9.3 "Manual").** `POST chart-of-accounts/start-blank` (GL_SETUP_MANAGE) replaces the chart with only the system accounts — the 5 roots + 39/390/3900 — through the same path and refusals as apply/upload (D-47). Result `{ accountsCreated: 8, defaultsAssigned: 1, status }`, then RecomputeAsync. It publishes `CoaUploadedEvent` with Format `BLANK` (history: "Blank chart of accounts started: 8 system accounts created."). AccountsCreated counts these system rows; the defaults step still needs real leaves.
- **D-61 (BE1) Delete refusal on every row.** `canDelete` / `deleteBlockedReason` live on the base `Account` model, so tree nodes, flat, subtree, ancestors and detail all carry them. `DeleteBlockedReasonsAsync(org, accounts)` computes them in one batch: 4 lookups (active children, default assignments, non-zero opening balances, mappings) whatever the count. The LocalDB test checks ≤ 5 SQL commands for the whole tree. Rules and order are D-48's.
- **D-40 (FIN) Sub-ledger totals are the original opening amounts.** `IOpeningSubledgerTotals` (Finance `OpeningSubledgerTotalsService`) sums the **original** base amount of OPENING documents, not what is still outstanding: the GL opening balance is as at the conversion date, and payments since then belong to post-conversion activity. Customer = Σ `BaseGrandTotal` of OPENING sales invoices not deleted and not CANCELLED; supplier = Σ `BaseTotalAmount` of OPENING bills not deleted and not Reversed (same document filters as the A40 date guard). A document without a stored base amount falls back to amount × its rate (1 when none). Rounded to 2dp.
- **D-41 (FIN) Currency.** `CurrencyCode` = the org's **sale** base (`ICurrencyService.GetBaseCurrencyIdAsync(org, Sale)` → org currency code), falling back to the opening documents' `BaseCurrencyCode`.
- **D-42 (FIN) Purchase base ≠ sale base.** Supplier bills are rate-locked to the purchase base; a group whose base differs from the sale base is converted with `ICurrencyService.ConvertAsync` at the opening balance date (today if unset). No rate on file → left unconverted (info only, never fails the wizard step; see residual).
- **D-43 (FIN) Opening stock value** = Σ `TotalCost` of the Finance product ledger's `OPENING_STOCK` entries for the org (posted by Inventory's A40 opening-stock import). Product-ledger costs carry no currency and are read as base. Later corrections (adjustments) are not netted — the figure is what was posted as opening.
- **D-44 (FIN) Date lock.** `OpeningBalanceDateService` takes `IEnumerable<IOpeningDateLockSource>` (optional ctor arg, DI supplies all registered). Before the existing checks, each source is asked in registration order; the first returning a date ≠ the requested one (a clear counts) → 409 "The opening balance date is locked by {Description} posted as at {yyyy-MM-dd}." Re-saving the locked date itself is allowed (no-op). The A40 opening-documents and QA-R1 opening-stock checks are unchanged; Inventory's `OpeningStockDateSource` registration is untouched. **Constraint for Accounting:** its lock source must not depend on `IOpeningBalanceDateService`/`IOpeningBalanceDateProvider` (would be a DI cycle).
- **D-50 (BE2) Fiscal years.** Create makes one period per month of the range plus period 13 "Year-End Adjustment" (the last day). A year is at most 12 months. A shorter first year gets fewer monthly periods (the last cut at the end date) and still period 13. Period names `MMMM yyyy` (invariant) from the period start. A blank name becomes `FY yyyy` / `FY yyyy-yy`; a duplicate name → 409 `"A fiscal year named \"{name}\" already exists."`. Reporting currency: the request's 3-letter code (upper-cased), else the org's **sale** base (Tenancy `IOrganizationCurrencyService` + Lookups `ICurrencyCodeLookup`, both optional), else 400 `"Enter the reporting currency: the organization's base currency could not be found."`. `hasPostings` = a **Posted** journal entry dated inside the year (the opening balance entry counts). PUT: blank name/currency = keep; new dates only while there are no postings **and** every period is Open (else 409); the periods are then regenerated (new uuids, all Open). A closed year is read-only (409 `"A closed fiscal year cannot be changed."`); closing again is a no-op. No delete (reset removes years).
- **D-51 (BE2) Periods.** `status` is case-insensitive. Open⇄Locked and Open/Locked→Closed are allowed; Closed→anything is 409 `"A closed period cannot be reopened."`. Closing is refused (409) while a Draft journal entry is dated in the period. Date edits support custom calendars (e.g. 4-4-5, one edit at a time): moving a monthly period's start moves the previous period's end, and moving its end moves the next period's start. The first start and the last end stay on the year's dates (400). Period 13 moves freely inside the year. After each edit, periods 1..12 must cover the year with no gap or overlap, and every period must end on or after its start (400 `"Period {name} would end before it starts."` / `"Period dates must fall within the fiscal year."`). A refused edit changes nothing. Date edits are refused while the year has postings or any closed period. `IFiscalPeriodGuard` = some **Open** period of a non-closed year contains the date.
- **D-52 (BE2) Defaults.** DEFAULT_OPENING_BALANCE always points at the active leaf 3900 when the chart has one; this is fixed on GET and on every save (event published). PUT on it → 400 `"The Opening Balance Equity default is assigned automatically to account 3900 and cannot be changed."`; save-all accepts it unchanged, empty or as 3900. Save-all validates every item first and saves nothing if any item fails: 400 `{ message, result: { problems: { defaultKey, message }[] } }`. Hard rules (400): `"Account not found."` (also another org's uuid), `"Only Level 4 accounts can be assigned as defaults."`, `"The default account must be active."`. An unknown key is 404 on the single PUT and a problem in save-all; a key listed twice in one save-all is a problem. After Complete, clearing a required default → 400 `"A required default cannot be cleared after the setup is complete."` (re-pointing it stays allowed). `AccountingDefault` gains `warning?` (type ≠ expected — never blocks) and `problem?` (the assigned account became inactive, a group, or missing). A row with a problem counts as unassigned in `assignedRequiredCount` and `validate.missingRequired`. Validate: `isValid` = nothing missing and no problems; warnings don't count.
- **D-53 (BE2) Opening balance page.** Rows = active leaves plus any account that has an entry (and, once posted, any with an opening balance). Draft: rows show the entries and 3900 shows 0 (the plug is in the summary). Posted: rows show the accounts' opening debit/credit, so 3900 shows the plug. Summary `difference` = Σ debits − Σ credits of the entries (never the plug); `plugSide` is `Credit` when debits exceed credits; extra `entryCount`. `conversionDate` = the copy taken at posting, else Finance's `IOpeningBalanceDateProvider`. Extra fields `isSkipped`, `postedAt`. `subledger` is **null** when Finance's `IOpeningSubledgerTotals` is not registered or throws. Its account balances are the net entry on the default A/R / A/P / Inventory account in its normal direction (null when that default is unassigned), plus `receivableAccountCode/payableAccountCode/inventoryAccountCode`.
- **D-54 (BE2) Batch save.** All-or-nothing: 400 `{ message, result: { errors: { accountUuid, accountCode?, message }[] } }`, where `message` = the single error or `"{n} opening balances are invalid."`. Besides the contract's sentences: `"Account not found."`, `"Account {code} is inactive."`, `"Opening balances cannot be negative."`, `"Account {code} is listed more than once."`, and notes > 500. Amounts are rounded to 4 dp; a 0/0 row deletes the draft; after posting → 409 `"Opening balances were already posted."`.
- **D-55 (BE2) Post.** Checks run in this order:
  1. already posted (409)
  2. skip path
  3. date not set (400)
  4. no fiscal year (400 `"Set up a fiscal year first."`)
  5. date outside the **earliest** year (400)
  6. no entries (400 `"Enter at least one opening balance, or skip this step."`)
  7. entries re-validated
  8. difference without `acknowledgeDifference` (400, contract sentence, amount `#,##0.00`)
  9. 3900 missing, only when a plug is needed (409)

  Number: `IDocumentNumberGenerator` with prefix `JE`, the year of posting and the org passed explicitly. When no generator is registered it falls back to the org's own max+1; a number already in the org's journal is skipped. Journal: date = conversion date, currency = the first year's reporting currency, reference `"Opening Balance Entry — yyyy-MM-dd"`, lines in account-code order with the plug last (memo "Opening balance difference"), totals including the plug. Accounts: opening debit/credit set, `CurrentBalance +=` the net in the normal direction, `HasTransactions`. A conditional UPDATE of the status row (`OpeningBalancesPostedAt IS NULL`) inside the transaction turns a concurrent second post into a 409. `OpeningBalancesBalanced` = true after a post (balanced or acknowledged).
- **D-56 (BE2) Skip.** Refused (409 `"Delete the draft opening balances before skipping, or post them instead."`) while drafts exist. It needs neither the date nor a fiscal year, and copies the date when set (the lock then pins it). No journal; event `Skipped = true`; entered = balanced = true.
- **D-57 (BE2) Date lock source.** `GlOpeningDateLockSource` (scoped `IOpeningDateLockSource`, Description "General ledger opening balances") reads only `CoaSetupStatuses`: `ConversionDate` when `OpeningBalancesPostedAt` is set, else null. Reset (D-17) clears both, which releases the lock.
- **D-58 (BE2) Mappings.**
  - **Create.** `systemType` and `syncDirection` are case-insensitive (direction defaults to None). `systemName` defaults to the system's display name. `externalAccountCode` is required (≤ 100). Another org's account → 404 `"Account not found."`.
  - **Credentials guard.** `connectionConfigJson` must be valid JSON (400 `"Connection settings must be valid JSON."`). No key at any depth may contain password/secret/token/apikey/api_key/clientsecret/client_secret/privatekey/private_key (case-insensitive, `-` read as `_`).
  - **PUT / DELETE.** `externalAccountCode` is required. Blank `systemName` = keep. `connectionConfigJson` null = keep, "" = clear. Re-activating re-checks the account. DELETE is a hard delete.
  - **Import.** Header names are case-insensitive; `sms_account_code` and `external_code` are required columns. Accounts are matched among active accounts by code (case-insensitive). Each bad line is reported (`line` = physical line, header = 1) and the good lines are saved in one transaction. An account listed twice in the file is refused on the later line. An update also refreshes `systemName`. The result is always 200 `{ created, updated, errors }`; an unreadable header or unknown systemType → 400.
  - **Export.** The 4 import columns plus `system_type,system_name,is_active`, UTF-8 BOM, CRLF. Values starting with `= + - @` are prefixed `'`. The export imports back.
- **D-59 (BE2) Dashboard.** Totals = Σ `CurrentBalance` of **all** leaf accounts (inactive included) per root type. `accountCount` = active accounts, all levels. `fiscalYear` = the year containing today, else the latest that started, else the earliest; `currencyCode` = its reporting currency (null without a year). Gated by `[RequiresGlSetup]`, plus any GL permission.

## QA findings (2026-10-13)
LocalDB HTTP E2E suite `tests/SMS.Integration.Tests/GeneralLedger/` — `GlChartE2ETests` (8), `GlSetupE2ETests` (6), `GlAccessE2ETests` (4); 18/18 green, each class run alone. Accounting unit suite 110/110 after the fixes.
- **QA-1 (fixed) — mapping export did not import back unchanged.** The export prefixes values starting with `= + - @` with `'` (formula guard, D-58), but the import stored the apostrophe, so export → import turned `=SUM(A1)` into `'=SUM(A1)`. `MappingCsv.Unescape` now removes the guard on import (`ExternalMappingService.cs`). Kept: E2E `Mappings_are_created_imported_exported_and_guarded` + unit `Update_delete_and_export`.
- **QA-2 (fixed) — mapping export line ends.** The export used `AppendLine` (LF on a Linux host); D-58 / the contract say CRLF. Now `\r\n` explicitly (`ExternalMappingService.ExportAsync`).
- **QA-3 (behaviour, by A37 design) — "feature off" is read-only, not closed.** Removing the `FEATURE_GENERAL_LEDGER` licence from an organization that had it leaves every GL **read** open (A37 D-6 ReadOnly level) and refuses every **write** with 403 `MODULE_NOT_LICENSED`. Only an organization that never had the feature (e.g. Basic, D-36) gets 403 on reads too. The test asserts exactly that; if the product wants a hard 403 on reads after un-licensing, it is an A37 registry decision, not an Accounting change.
- **QA-4 (contract text) — "The parent must be one level above (level {n})." cannot happen over the API.** `POST chart-of-accounts` derives the level from the parent, so an L3 can never be created under an L1 by hand; the only way is a file, which is refused by **R5** ("Account 113 references parent 1 which is not found or not at level 2."). A leaf parent gives 400 "Accounts can only be added under a group account (levels 1–3)." The sentence can be dropped from the contract.
- **QA-5 (contract text) — template writes.** A42 has only `DELETE api/finance/templates/{uuid}` (403 "System templates are read-only." on a system template, tested). PUT/POST template routes do not exist (404/405), so "PUT/POST on a system template → 403" is moot until tenant template authoring exists.
- **QA-6 (residual, design) — GL grants appear at the next start.** D-35's "roles allowed INVOICE_VIEW / SALES_INVOICE_VIEW get GL_VIEW" (and FINANCE_SETUP_MANAGE → all three) runs only in the startup seeder. A role that gains INVOICE_VIEW after start-up has no GL access until the API restarts, then silently gets GL_VIEW. The suite's "no GL permission" user (SALE_ORDER_VIEW + INVOICE_VIEW, created after start) relies on that. Needs a product decision (grant at role save, or drop the implicit rule).
