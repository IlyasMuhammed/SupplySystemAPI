Full reasoning for each is in `ADDENDUM-34-ANALYSIS.md` §3.

| # | Adopted |

| D-1 | A line whose effective route is MANUFACTURE is **make-to-order**: `FulfillmentMode = MAKE_TO_ORDER`, `DeficitQty = Quantity`, no reservation, no deficit job, no delivery at confirm, one production order for the full quantity |
| D-2 | A30 make-to-shortage stays keyed on `Product.SupplyMethod` for non-MANUFACTURE lines, unchanged. `AutoPoCreationJob` skips MAKE_TO_ORDER lines |
| D-3 | No flag auto-sync. A MANUFACTURE route can only be assigned to variants of products with `SupplyMethod = MANUFACTURE` and an org with MODULE_MANUFACTURING (400 otherwise) |

| D-5 | Confirm-gate blockers: `MANUFACTURING_DISABLED`, `NOT_MANUFACTURED`, `BOM_MISSING`, `PRODUCTION_WAREHOUSE_MISSING`, checked via `IManufacturingReadiness`. Line save stays free |
| D-6 | A MANUFACTURE route can't be an org default: set-default → 400; changing a default route's category to MANUFACTURE → 409 |
| D-7 | BUY/DROPSHIP are in the CHECK constraint, but the service refuses them (400 "not yet available"). A29 `DROP_SHIP` sourcing stays route-exempt |
| D-8 | A category change is refused (409) on system, default or in-use routes (variants, open SO lines, open production orders via Material `IFulfillmentRouteUsage`) |
| D-9 | Both MFG seeds go to every org (seeder + provisioning + startup backfill, matched by code). Hidden, refused and blocked when the org lacks MODULE_MANUFACTURING |
| D-10 | `LeadTimeDefaults` lives in **Inventory** (`inventory.LeadTimeDefaults`), one row per org. A missing row reads as 1/3/1/0/0/0; PUT upserts. No backfill |
| D-11 | `ProductVariant.LeadTimeDays` becomes the supplier override (API `supplierLeadTimeDays`). Chain: preferred `VariantSupplier` → default supplier row → `BusinessPartner.LeadTimeDays` (`ISupplierLeadTimeLookup`) → `Product.LeadTimeDays` → 0 |
| D-12 | No BOM operations. Days per level = `variant.ManufacturingLeadTimeDays ?? Product.LeadTimeDays (MANUFACTURE) ?? 1`. The total is always BOM-aware. No data copy |
| D-13 | Recurse when the component's product has SupplyMethod MANUFACTURE. Component stock = free stock in the parent's production warehouse. Depth 10 + visited set; a cycle gives 0 plus a warning component |
| D-14 | STOCK routes: supplier lead counts only when free stock (best single warehouse) is below the quantity; otherwise 0 with source "In stock" |
| D-15 | No persisted computed column. Lines get `CalculatedLeadTimeDays`, `CalculatedDeliveryDate`, `LeadTimeCalculatedAt`. The manual date is inquiry `EstimatedDeliveryDate`, quotation `PromisedDeliveryDate`, and a new SO `ManualDeliveryDate`. The effective date is computed in the models. Conversions copy the dates |
| D-16 | `POST …/lines/{lineUuid}/lead-time` for inquiry, quotation and SO. `PUT api/sale-orders/{uuid}/lines/{lineUuid}/delivery-date` (DRAFT, CONFIRMED, PARTIALLY_FULFILLED) under the order lock, with no re-pricing. Existing production orders are not rescheduled. The full SO POST/PUT round-trips the fields |
| D-17 | Production orders are created **after confirm commits**: under the order lock, register SALES_ORDER demands (no allocation run) and create one DRAFT PO per line, idempotently. Then plan the POs outside the lock. Recovery: `ProductionCreationPendingSince`, a sweep, and a "Create production orders" button |
| D-17a | **Amended 2026-10-04 (REV-01):** production creation registers **no** allocation demand. Otherwise any later allocation run fills the make-to-order line from free stock while its PO still makes the full quantity, which is double supply. Instead, MFG's FGR hook registers or extends the line's SALES_ORDER demand right before its post-commit `AllocateAsync`, sized so that the line's open demand never exceeds the finished goods received from this PO, minus what is already on deliveries or holds. This applies only while the SO is CONFIRMED or PARTIALLY_FULFILLED. Allocation is still not strict pegging (R-9) |
| D-30 | **Added 2026-10-04 (QA finding, pre-existing since A29/A30).** FGR never posted finished goods to the A29 product ledger, so sales invoices for any manufactured good failed at issue with 409. Fix: every FGR (make-to-order and make-to-shortage) appends **ADJUSTMENT / IN** at the FGR's own unit cost, inside the FGR transaction, with a reference to the FGR and PO. Material-consumption OUT postings are **not** added (a recorded gap: raw-material product ledgers aren't reduced by production issues). Owner: MFG |
| D-18 | The PO reuses `SourceType/SourceUuid/SourceLineUuid`. It gains `FulfillmentRouteUuid` (set only by the make-to-order path), `DeliveryOrderUuid`, `DeliveryNumber`, `DeliveryCreationPendingSince`. **No backfill** |
| D-19 | Planned dates: post = pick/pack + shipping (if SHIP) + sales buffer + QC + transfer. `RequiredDate = max(today, effective − post)`; start = `max(today, RequiredDate − (level days + mfg buffer))`. With no date: `RequiredDate` = today + the manufacturing total, start = tomorrow. Date-only |
| D-20 | The delivery is created when the PO turns COMPLETED (hook in `FinishedGoodsReceiptService`, after allocation, with no transaction or lock held). Quantity = min(accepted − already on non-cancelled deliveries from this PO, the line's outstanding). Plus a "Create delivery now" button (DELIVERY_CREATE) |
| D-21 | Deliveries from production ignore `PartialFulfillmentAllowed`. A shortfall sets `SaleOrderLine.ProductionShortfallQty`, adds a timeline entry and notifies. Zero yield is raised at QI (accepted 0) on make-to-order POs |
| D-21a | **Amended 2026-10-04 (REV-02):** `ProductionOutcome` carries `Completed`. `ProductionShortfallQty` and `PROD_SHORTFALL` are recorded only when the PO is final (COMPLETED). A "Create delivery now" made mid-production records no shortfall. Notifications are sent once (idempotent on replay) |
| D-22 | The cancel cascade covers **every** SALES_ORDER-sourced PO: DRAFT..READY with nothing issued are cancelled; IN_PROGRESS+ or issued ones are kept and reported. All open SALES_ORDER allocation demands are cancelled too (fixes pre-existing C-10) |
| D-23 | Notifications: existing `PROD_CREATED`; new `SO_DELIVERY_FROM_PRODUCTION`, `PROD_SHORTFALL`, `PROD_ZERO_YIELD`, `SO_PRODUCTION_FAILED`. Single recipients (A30 pattern) |
| D-24 | New code `LEAD_TIME_DEFAULTS_MANAGE`. The other gates follow analysis §4.8. Every new action is gated |
| D-25 | No `GET …/fulfillment`: extend the SO detail with `productionOrders[]`; the Production tab gets route and delivery columns |
| D-26 | A "Lead Times" tab on product detail (pick a variant, 8 components, source badges). Editable with STOCK_MANAGE |
