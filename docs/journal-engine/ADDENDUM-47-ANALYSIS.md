# Addendum 47 — General Ledger Journal Engine: analysis

Source: `SMS_FSD_Addendum_47.md` (SMS-FSD-ADD-047 v1.0, 2026-10-24) and `SMS_Task_Register_Addendum_47_Checklist.md`.
Builds on A42 (docs/general-ledger/) and A44 (docs/financial-posting/). Read Part A before changing anything.

## Part A — Reality check (spec vs. the code as it is)

The FSD was written against an assumed codebase. Where it conflicts with what A42/A44 actually built, the code wins
and the spec's *intent* is implemented in the existing shape.

| # | Spec says | Reality | Consequence |
|---|---|---|---|
| A-1 | `SMS.Finance` project, `FinanceDbContext`, `SMS.Finance.Interfaces/Services/Controllers` | The GL lives in **`SMS.Modules.Accounting`** with **`AccountingDbContext`** (schema `finance`). `SMS.Modules.Finance` is the SCM AR/AP module (invoices, payments) and is not the GL. | All A47 code goes into `SMS.Modules.Accounting`. |
| A-2 | `int org_id`, `int` ids everywhere, `nvarchar(450)` user columns | `Guid OrganizationId` + EF tenant filter (`ITenantScopedEntity`); `int Id` + `Guid Uuid`; users are `int?` ids (`CreatedBy`, `PostedBy`); PascalCase columns | New tables follow the A42 conventions (A42 D-1/D-2). The API takes and returns **uuids**, never int ids. |
| A-3 | `/api/v1/finance/...` | Every module uses `api/<module>/...` without a version; GL routes are `api/finance/...` (chart-of-accounts, fiscal-years, posting …) | Routes become `api/finance/journal-types`, `api/finance/journal-entries`, `api/finance/reconciliation`, `api/finance/trial-balance`, `api/finance/period-close`. |
| A-4 | M3/M4 **create** `finance.JournalEntries` / `JournalEntryLines` | **Both tables already exist** (A42 D-10, extended by A44): `EntryNumber`, `EntryType` (string), `Status` (string Draft/Posted), `TotalDebit/TotalCredit`, `CurrencyCode`, `SourceModule`, `SourceDocumentUuid`, `IdempotencyKey`, `ReversesEntryId`; lines have `DebitAmount/CreditAmount/Memo`. They hold the A42 opening journal and every A44 GL posting. | M3/M4 become **ALTER** migrations that add the missing columns and backfill them. No data is moved or renamed. |
| A-5 | `status` tinyint 0/1/2 | Strings (`JournalStatuses.Draft/Posted`), each list also a CHECK constraint (A42 convention) | Add `Reversed` to the string list + CHECK. |
| A-6 | `idempotency_key` **unique** per org | A44 D-13: one document's versions share a key (update = reversal + new journal under the same key; a void uses `key:void`). A unique index would break A44. | Keep it **non-unique**. Uniqueness is enforced where the spec needs it: manual entries (`manual:{uuid}`), `reversal:{uuid}`, `yearclose:{uuid}` through a **filtered unique index** on keys with those prefixes, plus the application check. |
| A-7 | Entry numbers `{prefix}/{year}/{seq:D4}`, `JournalEntrySequences` | Numbers are `JE-YYYY-NNNNN` from the Logistics document counter (A42 D-10); the local fallback is not concurrency-safe (A44 R-CORE-4). | New entries use the per-type sequence table (fixes R-CORE-4). **Existing journals keep their JE- numbers** (BR-JE-010: numbers are immutable). |
| A-8 | `currency_id` (int FK to lookups) | Currencies are **codes** (A42 D-7) | `CurrencyCode` everywhere. |
| A-9 | Line `debit/credit` in entry currency, `local_debit/local_credit` in reporting currency | A44 already converts to the base currency at posting: `DebitAmount/CreditAmount` **are base amounts**, and every A42/A44 balance and screen reads them | `DebitAmount/CreditAmount` stay the base (local) amounts. Added per line: `CurrencyCode`, `AmountCurrency` (signed amount in the transaction currency), `ExchangeRate`. Spec's `local_debit/local_credit` are therefore the existing columns; no duplicate columns. |
| A-10 | `ChartOfAccounts.current_balance += local_debit − local_credit` | A42 keeps `CurrentBalance` **in the account's normal direction** (credit-normal roots go up on credits) and A44 moves it atomically with `ExecuteUpdate` | Keep the A42 rule (one shared balance mover). The trial balance recomputes from lines, as the spec says. |
| A-11 | M7 SQL trigger sets `has_transactions` on line insert | `HasTransactions` is already set by the application on every post (A42 opening post, A44 `MoveBalancesAsync`). Task 122 also says it must not fire for drafts, which an insert trigger cannot know. | **No trigger.** The engine's single balance mover sets the flag (drafts also mark accounts used, as A44 does, so a used account cannot be deleted). |
| A-12 | `partner_id` int, `partner_type` | Partners are `Guid` (`FinancialTransactionLine.PartnerId`, `PartnerType Customer/Vendor` on the transaction) | `PartnerUuid` (Guid?) + `PartnerType`. |
| A-13 | `FiscalPeriods.status` CHECK `Open/Closed/Locked`, transitions in §5.2 | A42 BR-FP-005: Open ⇄ Locked, Open/Locked → Closed (final); `IFiscalPeriodGuard` allows Open only; year close (`POST fiscal-years/{uuid}/close`) needs every period Closed and posts nothing | Add `AdjustmentOnly` to the list + CHECK. The guard learns the entry kind (regular vs opening/closing). The existing year close stays for orgs that close without a closing entry; the new year-end close (C10) is a separate, stronger action. |
| A-14 | `JournalEntryBuilder` / `IJournalEntryBuilder` (A44) delegates to the engine | That class does not exist. A44's `InternalGlPostingTarget` writes journals itself (resolve roles → accounts, rounding line, update = reversal + new, void, draft when AutoPostToGL is off, app lock per document) | C11 = refactor `InternalGlPostingTarget` to build a `CreateJournalEntryRequest` and call the engine (create, sequence, period check, balance move), **keeping every A44 behaviour and test**. The gateway contract does not change. |
| A-15 | DocumentType enum with 10 values | `FinDocType` has 20 (SalesInvoice, CreditNote, Payment, PurchaseBill, BillPayment, VendorCredit, POSSale, POSReturn, SalesReceipt, RefundReceipt, SalesReturn, PurchaseReturn, InventoryAdjustment, ProductionCost, ProductionCompletion, ManualJournal, BankFee, Expense, DepositSlip, OpeningBalance) | Resolver covers all 20 (D-12). |
| A-16 | React 18 UI, routes `/finance/...` | Angular, GL pages under `/portal/pages/finance/gl/*`, `sf-*` kit + `--sms-*` tokens | New pages under `/portal/pages/finance/gl/` (journal-entries, journal-types, reconciliation, trial-balance, period-close). |
| A-17 | Permissions `Finance.View`, `Finance.JournalEntry.Create` … | Permission codes are upper snake (`GL_VIEW`, `GL_ACCOUNT_MANAGE`, `GL_SETUP_MANAGE`) under FEATURE_GENERAL_LEDGER | New `GL_*` codes (D-15). |
| A-18 | FluentValidation validators | The Accounting module validates in its services (BadRequest/Conflict exceptions with user-facing text); no FluentValidation | Service validation, A42 style. Error codes JE-001..JE-015 are kept as `errorCode` in the response. |
| A-19 | "Domain events" (`JournalEntryPostedEvent`, `FiscalYearClosedEvent`) | A42 has `AccountingEvents` → immutable `GlSetupHistory` rows | Events are written there. |
| A-20 | Gateway step 5 in the same transaction as the source document | A44 posts after commit and per target (D-7); an internal-GL failure never blocks the QuickBooks outbox | TS-GW-005 already holds; tested as such. |
| A-21 | Register header says 348 tasks | The table numbers 001–468 | The tracker uses 001–468. |

## Part B — Decisions (recommended defaults adopted, per the standing "proceed with recommendations" rule)

| ID | Decision |
|---|---|
| D-1 | Everything in `SMS.Modules.Accounting` / `AccountingDbContext`; A42 entity conventions (A-1, A-2). |
| D-2 | `JournalEntries`/`JournalEntryLines` are extended, not recreated (A-4). New header columns: `JournalTypeId` (FK, NOT NULL after backfill), `DocumentDate`, `FiscalYearId`, `FiscalPeriodId` (FKs, nullable for journals dated outside any period), `ExchangeRate`, `ReversedByEntryId` (self FK), `ReversalReason`, `IsOpeningEntry`, `IsClosingEntry`, `LineCount`, `UpdatedAt/UpdatedBy`. Existing `ReversesEntryId` is the spec's `reversal_of_entry_id`. |
| D-3 | New line columns: `PartnerUuid`, `PartnerType`, `CurrencyCode`, `AmountCurrency`, `ExchangeRate`, `CostCenter`/`Project` (strings, as the gateway sends them), `TaxCode`/`TaxAmount`, `Reconciled`, `ReconcileGroupId`, `ClearingEntryId`, `ClearingDate`, `AmountResidual`, `CreatedAt`. Backfill: `AmountResidual = Debit − Credit`. |
| D-4 | Statuses stay strings: Draft / Posted / **Reversed**. A44 reversals (update/void) also mark the original Reversed and set `ReversedByEntryId` (backfilled for existing pairs). |
| D-5 | Idempotency key stays non-unique (A-6); filtered unique index on `manual:`, `reversal:`, `yearclose:` keys. |
| D-6 | Journal types per org, seeded with the 7 system types when the A42 setup completes and by a guarded migration for orgs already set up. Existing journals backfilled: OPENING_BALANCE → OPEN (`IsOpeningEntry`), A44 types via the resolver (D-12). |
| D-7 | Numbering: `{prefix}/{fiscal year start year}/{seq:D4}` from `JournalEntrySequences`, row taken with `UPDLOCK, HOLDLOCK` in the posting transaction. Journals dated outside any fiscal year (possible for A44 drafts only) use the calendar year. Existing JE- numbers kept. The sequence grows past 9999 without truncation. |
| D-8 | Base amounts stay in `DebitAmount/CreditAmount` (A-9). The engine rounds conversions to 2 dp like A44, rounding difference to DEFAULT_ROUNDING for gateway posts; a manual entry must balance in base itself. |
| D-9 | `CurrentBalance` keeps the A42 normal-direction rule; one shared balance mover (moved from `InternalGlPostingTarget`) used by post, reverse and year-end close (A-10). |
| D-10 | No SQL trigger for HasTransactions (A-11). |
| D-11 | Period guard: Open accepts all; AdjustmentOnly accepts only `IsOpeningEntry`/`IsClosingEntry` entries; Locked/Closed nothing; a closed fiscal year nothing (BR-PC-007). Transitions: Open → AdjustmentOnly/Locked, AdjustmentOnly → Open/Locked, Locked → Open (reopen), Locked → Closed (final). Locking or closing a period with drafts is refused (BR-PC-001), as A42 already does for Closed. |
| D-12 | Resolver: SalesInvoice, CreditNote, SalesReturn, POSSale, POSReturn, SalesReceipt, RefundReceipt → SALE; PurchaseBill, VendorCredit, PurchaseReturn, Expense → PURCH; Payment, BillPayment, DepositSlip, BankFee → CASH when a line uses DEFAULT_CASH, else BANK; InventoryAdjustment, ProductionCost, ProductionCompletion, ManualJournal → MISC; OpeningBalance → OPEN. A deactivated target type falls back to MISC. |
| D-13 | `requires_partner` on SALE/PURCH applies to **manual** entries only. Gateway journals carry the partner where the source sends one; A44 tax/revenue lines have no partner, so enforcing it on gateway posts would fail every invoice. |
| D-14 | Reversal of a manual or gateway journal: mirror lines, auto-posted, dated the original date unless given, key `reversal:{uuid}`; original → Reversed; lines of the same account auto-reconciled (BR-RV-008). Reversing a gateway journal by hand is allowed only with GL_JOURNAL_REVERSE and is recorded; the source document is untouched (warning shown). |
| D-15 | Permissions (all under FEATURE_GENERAL_LEDGER): GL_VIEW (read journals/types), GL_JOURNAL_CREATE, GL_JOURNAL_EDIT, GL_JOURNAL_DELETE, GL_JOURNAL_POST, GL_JOURNAL_REVERSE, GL_RECONCILE_VIEW, GL_RECONCILE_EXECUTE, GL_REPORTS_VIEW, GL_PERIOD_CLOSE_VIEW, GL_PERIOD_CLOSE_EXECUTE, GL_PERIOD_CLOSE_ADMIN; journal-type CRUD = GL_SETUP_MANAGE. Organization Admin and System Admin get all; implicit GL_VIEW holders get the three *_VIEW codes. |
| D-16 | Reconciliation: same org, same account, posted, ≥ 2 lines, a line in one active group at a time (BR-RC-008; partial groups: a line keeps its group until fully cleared, a second reconcile on a partially reconciled line is refused — unreconcile first). Group numbers `REC/{year}/{seq:D4}` from the same sequence table (journal type null). |
| D-17 | Trial balance computed from posted lines in base currency (spec §12.4), Level-4 accounts, closing entries excluded by default, zero-activity accounts hidden. CSV export server-side, as other GL exports. |
| D-18 | Year-end close: all periods 1–12 Locked or Closed, period 13 Open/AdjustmentOnly if it exists, no drafts; retained earnings defaults to DEFAULT_RETAINED_EARNINGS (must be a leaf Equity account); closing JE (type CLOSE, `IsClosingEntry`, dated the year end, period 13 if it exists else 12, key `yearclose:{year uuid}`) auto-posted; year `IsClosed`; all periods Closed. A second run returns the existing result. |
| D-19 | C11: `InternalGlPostingTarget` delegates journal creation to the engine and keeps all A44 behaviour (A-14). All A44 unit and E2E tests must stay green unchanged except for the number format. |
| D-20 | UI pages under `/portal/pages/finance/gl/`: journal-entries (list, create/edit, detail with post/reverse), journal-types, reconciliation, trial-balance (+ account ledger drill-down), period-close. Menu items in the existing General Ledger group, guarded by the D-15 codes. |
| D-CORE-1 | The M8 seed (and the on-demand seeder) covers organizations whose setup is Complete **and** any organization that already has journals (an A42 opening journal exists before Complete; every journal needs a JournalTypeId before the column turns NOT NULL). The seeder also runs before any journal is written, under an application lock per organization. |
| D-CORE-2 | Until C11 (GW) the A42 opening post and the A44 target keep writing journals themselves (JE- numbers, own numbering) but call `JournalEntryWriter.StampLegacyAsync` (journal type by D-12, fiscal year/period, opening flag, line count, line currency/residual) and move balances through `GlBalanceMover`. A44 reversals are **not yet** marked Reversed at write time (the backfill did it for existing pairs) — GW does it in C11 (D-4). `AccountingDbContext` also fills the derived line columns of any new line a writer left empty. |
| D-CORE-3 | One guarded migration `A47_JournalEngine` with the M-steps as sections in the spec's order (M1, M8, M2, M6, M3, M4, M5; M7 dropped), instead of eight migrations. Drifted rows never fail a CHECK: it is added WITH NOCHECK (still enforced on writes) when existing rows violate it. |
| D-CORE-4 | "Posted" for every balance/report/year-end computation means `Status IN ('Posted','Reversed')` (a Reversed entry was posted; its reversal cancels it). A42's "year has postings" now counts Reversed too. |
| D-CORE-5 | Journal type code **and** sequence prefix are unique per organization (two types sharing a prefix would share entry numbers); kind stored as a string list (Sale … Closing), one Opening and one Closing type by filtered unique indexes. A system type's code/kind are fixed; OPEN/CLOSE stay auto-post; a prefix is fixed once numbered; custom unused types can be deleted (DELETE) and any type re-activated (PATCH activate) — both additions to §16.1. |
| D-CORE-6 | Name snapshots next to the int user ids: `CreatedByName`, `PostedByName`, `ModifiedByName` (header) and `PartnerName` (line), for display without cross-module lookups. Header `ModifiedAt/ModifiedBy` are the spec's updated_at/updated_by. Line `Memo` is the spec's description; `EntryType` is the spec's source_document_type (FinDocType upper snake, MANUAL_JOURNAL, YEAR_END_CLOSE). |
| D-CORE-7 | Sequences: `JournalEntrySequences(OrganizationId, JournalTypeId?, FiscalYearId?, SequenceYear)` unique; null type = reconciliation numbers (REC/{year}/{seq}), null fiscal year = journals dated outside every year. Label = fiscal year start year (`yyyy-MM` for a second fiscal year starting in the same calendar year); a number already used is skipped. Raw ADO batch (UPDLOCK, HOLDLOCK) in the caller's transaction (own transaction when none); in-memory: tracked row. |
| D-CORE-8 | Journal lines get a `Uuid` (unique) so reconciliation and ledgers address lines by uuid (A-3). |
| D-CORE-9 | A fiscal year's dates/period dates cannot change while draft journals are dated in it (drafts reference the periods by FK, Restrict; multiple cascade paths rule out SET NULL). |
| D-CORE-10 | Edit/delete through the API only for manual drafts (key `manual:`); a source-document draft (A44, AutoPostToGL off) can only be posted (R-CORE-1) — deleting it would orphan the posting log. A concurrent second post/edit/delete is caught by a conditional UPDATE/DELETE (409 JE-014). |
| D-CORE-11 | Journal-entry and journal-type routes carry `[RequiresGlSetup]` (post-setup GL routes, A42 D-4). Reads accept GL_VIEW, either A42 manage code or any GL_JOURNAL_* code. Creating with `postImmediately` or on an auto-post type also needs GL_JOURNAL_POST. `clientRequestId` makes a manual create idempotent (`manual:{id}`); without it each create is new. |
| D-CORE-12 | Error codes JE-001..JE-015 defined by CORE (the spec names them but gives no list) — API-CONTRACT §0; RR uses JE-015 and RC-001..008, RPT PC-001..010. Validation answers 400 with every error (`result.errors[]`, line numbers), state conflicts 409. Period/account refusals are 400. |
| D-CORE-13 | Manual entries: base = amount × rate rounded to 2 dp (D-8); balance checked in the transaction currency (when all lines share one foreign currency) and in base, tolerance < 0.01 (CK_JournalEntries_Balanced). Spec step 5 "root type appropriate for the direction" is not enforced (contra entries are legitimate). The partner is looked up through `IPartnerRoleLookup` when registered. |
| D-CORE-14 | Engine seams for RR/RPT/GW: `JournalDraft.AmountsInBase` (lines already in base), `AllowInactiveAccounts` (reversal), `SkipPeriodCheck` (year-end close into a Locked period 12 when there is no period 13; a closed year is still refused). `IJournalReversalService` is RR's interface; `IJournalEntryService.ReverseAsync` delegates to it and returns RR's `JournalReversalResultModel`. The shared `AccountRefModel` (A42) gained `rootType`. |
| D-CORE-15 | D-15 grants: GL_VIEW holders (by the A42 rules, or allowed GL_VIEW explicitly, unless GL_VIEW was switched off) get GL_RECONCILE_VIEW, GL_REPORTS_VIEW, GL_PERIOD_CLOSE_VIEW; admins get all via PermissionCodes.All; GL_SETUP_MANAGE's description now mentions journal types. |
| D-CORE-16 | SR-FE-2 — the A42 read GETs fiscal-years (list/one/periods), chart-of-accounts (tree/flat) and accounting-defaults also accept every A47 code (`AccountingCaller.CanReadGlLookups`), so a custom role holding only journal/reconcile/report/close codes keeps its year selector and account pickers. SR-RPT-1 declined: the A42 period PUT keeps the A42 transitions; D-11 lives on the A47 period-close routes. RR C-3/C-4 and RPT C-5..C-7 accepted (contract C-9). |
| D-CORE-17 | The A44 target seeds the journal types before opening its posting transaction (short per-org seeding lock, never held across a posting). Raw test fixtures that insert journals must set JournalTypeId (GeneralLedger/GlKit `EnsureMiscJournalTypeSql`). |
| D-21 | Migrations are guarded (idempotent `Up`), because API start migrates SMSGlobal. One migration per spec step where practical; M7 (trigger) is dropped (D-10). |
| D-RR-1 | Reversal (C7) = `JournalReversalService` over `JournalEntryWriter.CreateAsync(post:true)`: mirror lines (sides swapped, `AmountCurrency` negated, partner/description/dimensions/tax copied, `AmountsInBase`, `AllowInactiveAccounts`), header copies EntryType/SourceModule/SourceDocumentUuid/Reference/currency/rate/opening-closing flags; reason required (≤ 200, trimmed) and stored on **both** entries. One transaction; on SQL Server an app lock per entry (`glrev:`) then per account (`glrec:`, ascending) before reading lines; the unique `reversal:{uuid}` key is the fallback guard (DbUpdateException → 409). Event `JournalEntryReversedEvent` after commit. |
| D-RR-2 | Reversal period = D-11 with the original's flags: a regular entry cannot be reversed into an AdjustmentOnly period (D-11 overrides BR-RV-003's "or AdjustmentOnly"); opening/closing entries can. Refusal texts are the reversal's ("Reversal period is …"), codes JE-005..008; a closed year → "Fiscal year is closed". An inactive journal type falls back to MISC (D-12). |
| D-RR-3 | Not reversible (409 JE-015): Draft, Reversed, a reversal itself (CK_JournalEntries_ReversalLinks), the A42 OPENING_BALANCE journal, and the YEAR_END_CLOSE entry (added to the contract's list: the year-end close is undone by reopening, not by a reversal into a later year). If a `reversal:` journal exists while the original is not marked (interrupted legacy state), the call repairs the link and returns it (200). |
| D-RR-4 | BR-RV-008: per account one Full group over the original's lines + their mirrors, clearing entry = the reversal, clearing date = the reversal date; the whole account is skipped when any original line on it is already reconciled (its mirror stays open as e.g. a customer credit). Mirrors are matched by position (the writer renumbers 1..n). |
| D-RR-5 | Reconcile (C8) via `JournalReconciler` (no transaction/save, shared with the reversal): Full when |Σ residual| < 0.01 (all residuals 0); Partial: smaller side cleared, larger side reduced **oldest first** (entry date, line id) — the contract's rule, not the FSD's "proportionally". Cleared lines (residual 0) are `Reconciled` even in a Partial group; every line keeps the group (D-16), so a partially reconciled line is refused (RC-004) until the group is undone. Clearing entry = the latest entry of the group (date, id) for all cleared lines, date = its entry date. Group number from `NextReconcileGroupNumberAsync` with today's date; CurrencyCode = the reporting currency of the clearing date's fiscal year. |
| D-RR-6 | Lines of **Reversed** entries count as posted for reconciliation (D-CORE-4): after undoing a reversal's auto-group they can be matched again. |
| D-RR-7 | Open items: Posted/Reversed, not Reconciled, residual ≠ 0 (partials included with their group), capped at 2000 oldest first (narrow by partner/dates). 404s (line, group, account) are plain NotFoundException texts without `errorCode` — the JournalErrorFilter only codes 400/409. |
| D-RR-8 | Suggest: candidates = open lines of the account on the opposite side, not in a group, not selected (300 max; the selection's partner first, then oldest). Order: exact single lines, exact sets of 2–4 (search over the first 25), then the nearest non-exact (single lines and the oldest-first run that covers the selection) by |residualAfter|; default 10, max 50. A selected line in a group → RC-004. |
| D-RPT-1 | Trial balance, account balance, ledger and year-end balances read lines of entries `Status IN ('Posted','Reversed')` (D-CORE-4) in base amounts, aggregated in SQL (GROUP BY account, conditional SUMs over lines joined to entries; the organization explicit, tenant filter ignored). Services: `Services/Reports/TrialBalanceService.cs`, `Services/PeriodClose/PeriodCloseService.cs`. |
| D-RPT-2 | Level-4 accounts only; an **inactive** leaf account with activity is still listed (hiding it would unbalance the report); `includeZeroBalances` lists active leaves without activity. `includeOpeningBalances=false` = opening 0, closing = period. Range: dates, else `fiscalYearUuid`, else (extra) `fiscalPeriodUuid`; `fiscalYear` in the report = the asked year or the one containing both dates. |
| D-RPT-3 | Account balance (`asOfDate` default today) and ledger include closing entries (real postings); the ledger takes an extra `includeClosingEntries` (default true) so the TB drill-down can pass its flag. Both refuse a group account ("Choose a Level 4 account."). Ledger order entryDate, entryNumber, entry id, lineNumber; page size 1–500 (default 50); a page's running balance = opening + Σ of the rows ordered before its first row (range predicate on the sort key — a SUM over TOP(n) took 46 s on LocalDB, see task 428). |
| D-RPT-4 | Period close per D-11/contract §6 with codes PC-001..PC-010 (JournalConflict/ValidationException → `result.errorCode`). Same-status and non-D-11 moves → PC-004 (e.g. reopen an Open period, Locked → AdjustmentOnly). BR-PC-001 drafts check on Locked, AdjustmentOnly and Closed: drafts whose `FiscalPeriodId` is the period, or unassigned and dated inside it (a 12-31 draft of period 12 does not block period 13). `allowedActions` by state and the caller's EXECUTE/ADMIN. Every change → `FiscalPeriodStatusChangedEvent`. |
| D-RPT-5 | **Deviation from contract §6 ("closing entries excluded")**: the year-end P&L balances include `isClosingEntry` entries (manual year-end adjustments posted into period 13 / an AdjustmentOnly period are part of the year's P&L — excluding them would leave P&L accounts unzeroed); only entries keyed `yearclose:` are left out. Recorded as contract change C-5. |
| D-RPT-6 | Closing entry: type CLOSE (`JournalTypeResolver.ByCodeAsync`, MISC fallback when CLOSE is inactive), `YEAR_END_CLOSE`, `IsClosingEntry`, `AmountsInBase`, dated the year end, period 13 when it exists; without period 13 `SkipPeriodCheck` posts it into the Locked period 12. One transaction: entries, year `IsClosed/ClosedAt/ClosedBy`, every period Closed; events after the commit (JournalEntryPosted per entry, FiscalYearClosed). A concurrent second close hits the filtered unique `yearclose:` key → answered with the winner's result (verified on LocalDB). |
| D-RPT-7 | More than 499 Revenue/Expense accounts with a balance: several closing entries (keys `yearclose:{uuid}`, `yearclose:{uuid}:2` …), each balanced by its own retained-earnings line (engine limit 500 lines). Result `closingEntry` = the first, `closingEntries` (extra) all. |
| D-RPT-8 | A year with no Revenue/Expense balance closes without an entry (`closingEntry` null). `execute` on a year already closed — by the year-end close or by the A42 `fiscal-years/{uuid}/close` — returns `alreadyClosed:true` with the existing entry (or none), never an error. |
| D-RPT-9 | Balance/ledger routes answer on both `api/finance/trial-balance/accounts/{uuid}/balance|ledger` (contract §5 table, relative to its section route) and `api/finance/accounts/{uuid}/balance|ledger` (FSD §16.4 / task brief). Controllers carry `[RequiresGlSetup]` + `[JournalErrorFilter]`. |
| D-FE-1 | Menu: the five A47 pages sit in Finance › General Ledger (after Chart of Accounts). The group now opens for any GL code (A42 three + every A47 code) and **every entry carries its route's own gate** (A42 entries GL_VIEW/GL_ACCOUNT_MANAGE/GL_SETUP_MANAGE, Posting + INTEGRATION_VIEW/MANAGE, Dashboard via `alsoRequired` because its route also waits for setup).
