| Dotted / snake permission codes `crm_view_leads` | UPPER_SNAKE (`POS_ORDER_VIEW`) + prefix→module map | `CRM_VIEW_LEADS` …, prefix `CRM_` → MODULE_CRM (D-3) |

## Adopted decisions
- **D-1 Module.** New `SMS.Modules.Crm` (schema `crm`), references only SMS.Shared (A38 pattern). Other modules are reached through `CrmContracts.cs` seams implemented in the owning module: `ICrmAccountGateway` (Suppliers — accounts & contacts), `ICrmSalesDocumentGateway` (Demand — create inquiry/quotation, read linked documents and sale orders). Migrations guarded/idempotent, applied by `UseCrmModule()` on start (shared-DB rule).
- **D-2 Conventions.** int `Id` + Guid `Uuid` (API uses uuids), Guid `OrganizationId` with the tenant query filter + explicit org filter in every query (super admin bypass), PascalCase columns, statuses as strings, users int, money decimal(18,2), currency = 3-letter code validated against the org's ACTIVE currencies (`IOrgCurrencyLookup.GetByCodeAsync`). Account = BusinessPartners.UUID (Guid), contact = SupplierContacts.Id (int). Soft delete (`IsDeleted`) filtered explicitly. `Leads.FullName` is a stored column kept in step by the entity (a SQL computed column would not exist in the in-memory test store). `Campaigns.ActualLeads` counts leads ever attributed to the campaign (create, or a later change to it); it is not lowered when a lead is deleted — the campaign detail shows the live count by status beside it.
- **D-3 Permissions.** 21 codes, Appendix A names upper-cased: CRM_VIEW_LEADS, CRM_CREATE_LEAD, CRM_EDIT_LEAD, CRM_ASSIGN_LEAD, CRM_QUALIFY_LEAD, CRM_CONVERT_LEAD, CRM_DISQUALIFY_LEAD, CRM_REOPEN_LEAD, CRM_DELETE_LEAD, CRM_VIEW_OPPORTUNITIES, CRM_EDIT_OPPORTUNITY, CRM_CLOSE_OPPORTUNITY, CRM_REOPEN_OPPORTUNITY, CRM_VIEW_ACTIVITIES, CRM_CREATE_ACTIVITY, CRM_EDIT_ACTIVITY, CRM_DELETE_ACTIVITY, CRM_EXPORT_TIMELINE, CRM_VIEW_CAMPAIGNS, CRM_MANAGE_CAMPAIGNS, CRM_ADMIN. Role editor group "CRM". Create-inquiry/quotation/order also need SALE_INQUIRY_CREATE / SALE_QUOTATION_CREATE / SALE_ORDER_CREATE (the spec's demand_create_*).
- **D-4 Roles.** New built-in roles (global, seeded by code like the POS roles): **SALES_REP** "Sales Representative" = every Appendix A "Sales Rep" code + CUSTOMER_VIEW + SALE_INQUIRY_VIEW/CREATE + SALE_QUOTATION_VIEW/CREATE + SALE_ORDER_VIEW/CREATE; **SALES_MANAGER** "Sales Manager" = all CRM codes except CRM_ADMIN + the rep's sale codes + SALE_INQUIRY_EDIT, SALE_QUOTATION_EDIT/SEND, SALE_ORDER_EDIT/CONFIRM, CUSTOMER_CREATE/EDIT. System Admin / Org Admin get all through `PermissionCodes.All`. No existing role is granted CRM codes.
- **D-5 "(own)".** A caller holding the edit/close permission but NOT CRM_ASSIGN_LEAD (the manager marker) may change only records they own: lead / opportunity assigned to them (or, when unassigned, created by them); activity performed or created by them. Others → 403 "You can only change leads assigned to you." Managers and admins are unrestricted. Reading is not restricted (spec gives view to all reps).
- **D-6 Module & features.** `MODULE_CRM` becomes available (not core), dependency MODULE_CRM → MODULE_CUSTOMERS. Plans: Standard + Enterprise on, Basic off; existing organizations follow their plan (CRM touches nothing until used — unlike POS, D-2 of A38). Features: FEATURE_CRM_LEAD_MANAGEMENT, FEATURE_CRM_OPPORTUNITY_MANAGEMENT, FEATURE_CRM_ACTIVITY_TRACKING (core), FEATURE_CRM_CAMPAIGN_TRACKING (toggleable), FEATURE_CRM_LEAD_ASSIGNMENT, FEATURE_CRM_LEAD_SCORING, FEATURE_CRM_LEAD_WIDGET, FEATURE_CRM_EXTERNAL_SYNC (coming soon). All CRM endpoints `[RequiresFeature(MODULE_CRM)]`; campaign endpoints also FEATURE_CRM_CAMPAIGN_TRACKING (off → a lead's campaign reference is refused, public API ignores campaign_code with no error). Create inquiry/quotation/order refuse (400) when MODULE_DEMAND is off.
- **D-7 Seed data.** 14 lead sources + 8 pipeline stages are created per organization lazily and idempotently on the organization's first CRM call (`CrmSeeder.EnsureAsync`, guarded by the unique indexes) — "on CRM activation" without a hook into Tenancy; also run for every org at startup (best effort).
- **D-8 Numbers.** `IDocumentNumberGenerator` prefixes `LD` and `OP` → LD-2026-00001, OP-2026-00001 (house 5-digit format, per org per year). Drawn after validation.
- **D-9 Lead state machine** (§6.3): NEW→CONTACTED (needs a contact activity, BR-08), NEW/CONTACTED/QUALIFIED→DISQUALIFIED (reason required), CONTACTED→QUALIFIED, QUALIFIED→CONVERTED only via convert, DISQUALIFIED→NEW only with CRM_REOPEN_LEAD (clears disqualified_at, keeps history). CONVERTED terminal: no edit, assign, status change, delete (BR-06). `PATCH status` accepts CONTACTED / QUALIFIED / DISQUALIFIED / NEW and applies the same rules as the dedicated endpoints (incl. permissions). `LeadStateMachine` is a pure class (allowed transitions table) used by the service and the FE action buttons.
- **D-10 Contact activities & stages.** An activity "counts as contact" when its type is PHONE_CALL, MEETING, EMAIL_SENT, EMAIL_RECEIVED, SITE_VISIT, DEMO, PRESENTATION or FOLLOW_UP and it is not a still-open scheduled one (scheduled_date set and not completed). Logging such an activity on a NEW lead moves it to CONTACTED (BR-08 auto). Pipeline stage is separate from status: a new lead gets the first active LEAD stage (team stages if the lead's team has any); CONTACTED / QUALIFIED move the stage forward to INITIAL_CONTACT / QUALIFICATION only when the lead is still at an earlier stage (codes looked up; missing codes = no move). Kanban drag = `PATCH /leads/{id}/stage` (any active LEAD stage of the lead's pipeline; open leads only). Lead kanban shows NEW/CONTACTED/QUALIFIED leads.
- **D-11 History.** New `crm.RecordHistory` (EntityType LEAD|OPPORTUNITY, EntityId, Kind STATUS|STAGE|ASSIGNMENT, From, To, Reason, UserId, At). Written on every status, stage and owner change; it is the timeline's "status change" / "stage change" source and the "created" entry.
- **D-12 Opportunities.** Only via conversion (no create endpoint, BR-11). Stage moves among the pipeline's OPPORTUNITY stages; moving onto an is_won / is_lost stage by drag is refused ("Use Won / Lost"). **Won**: needs a linked sale order with status CONFIRMED, PARTIALLY_FULFILLED, FULFILLED, INVOICED or CLOSED (BR-12, latest such order); sets actual_revenue = its GrandTotal, currency = its currency code, actual_close_date = today, stage = won stage; WON is terminal. **Lost**: reason required (≤500), optional competitor; stage = lost stage. **Reopen** LOST→OPEN (CRM_REOPEN_OPPORTUNITY): clears close date, reason, competitor; stage = first open OPPORTUNITY stage. Won/Lost/Reopen are refused on the wrong status (409).
- **D-13 Opportunity → SCM documents.** Demand owns the link: new nullable `SourceOpportunityUuid` on SaleInquiry, SaleQuotation, SaleOrder (+ SaleOrderSourceType FROM_OPPORTUNITY), propagated down the chain (quotation from inquiry, SO from quotation keep the opportunity). `create-inquiry` → RECEIVED inquiry (customer = account, assignee = opportunity owner, notes = topic) — lines are added on the inquiry page. `create-quotation` → from the linked inquiry when it is REVIEW_COMPLETE, else an empty DRAFT quotation for the account. `create-order` → not created server-side (a sale order needs lines): the API returns a prefill `{ accountUuid, opportunityUuid, acceptedQuotationUuid? }` — the FE opens the accepted quotation (convert there) or the new sale order form prefilled with the customer + `sourceOpportunityUuid` (the SO create request accepts it → source type FROM_OPPORTUNITY). CRM reads the links back through `ICrmSalesDocumentGateway.ListForOpportunityAsync` and caches the latest uuid per kind in `SourceInquiryUuid / SourceQuotationUuid / SourceOrderUuid` (refreshed on read and on Won).
- **D-14 Documents.** `crm.ActivityDocuments` (spec columns) + `crm.ActivityFiles` (bytes varbinary(max), file name, content type, size) — never on disk. Upload rules = `UploadRules` (20 MB, allow-list). Attach: `POST /activities/{id}/documents` (multipart) and the timeline "+ Document" = creates a DOCUMENT_SHARED activity then attaches. Pipeline stage captured from the parent at share time. Download `GET /api/crm/documents/{uuid}/content` (CRM_VIEW_ACTIVITIES), delete `DELETE /api/crm/documents/{uuid}` (CRM_EDIT_ACTIVITY, own rule).
- **D-15 Timeline & export.** Server merges, sorts desc and pages: ACTIVITY, DOCUMENT, STATUS_CHANGE, STAGE_CHANGE, ASSIGNMENT, CREATED, CONVERTED, SCM_DOCUMENT (inquiry/quotation/order created). Opportunity timeline = its own entries + the source lead's entries, lead ones flagged `fromLead` (FE draws the "Activities from Lead" separator). Excel export: ClosedXML 0.104.2, sheets Summary / Timeline / Documents, bold frozen header, auto width, date format. PDF not built (R-1).
- **D-16 Public lead API.** `POST /api/public/crm/leads` with `X-Api-Key`. Keys in `crm.LeadApiKeys` (SHA-256 hash, prefix shown, name, per-minute limit default 100, active, last used); managed by CRM_ADMIN (`/api/crm/api-keys`, key shown once). Fixed-window per-key counter in memory → 429. Lead created NEW, unassigned, created-by = the system user 0 recorded as "API: {key name}". source_code / campaign_code resolved in the key's org (unknown code → 400).
- **D-17 Events.** The 11 Appendix B events are records published after commit through `ICrmEventPublisher` (in-process, DI `ICrmEventHandler<T>` handlers, a failing handler is logged, never fails the request). Built-in handler: LeadAssigned → in-app notification to the new assignee.
- **D-18 Isolation** (§8.5, BR-21..23): cross-references always filter `AccountId = current` (contact list additionally `ContactPersonId`); a lead without account shows none. Every query filters the caller's org explicitly.
- **D-19 Conversion.** One service call: (1) lead QUALIFIED, (2) account: existing → must be an active partner of the org; a vendor-only partner becomes a customer too (gateway `EnsureCustomerAsync`); new → customer via the A37 customer rules (code C-nnnnn, CustomerType COMPANY, or INDIVIDUAL when company_name = full name), (3) contact: existing → must belong to that account; new → SupplierContact under the account, (4) opportunity OP-…, first OPPORTUNITY stage, carries topic/description/revenue/close date/currency/team/owner/campaign, (5) lead CONVERTED with converted_* and account/contact links. Account/contact creation is in Suppliers' transaction, CRM's writes in CRM's — if CRM's save fails after a new account was created, the account stays (R-3) and a retry links it as an existing match. Duplicate suggestions (top 5 by name LIKE / email / phone) via `GET /leads/{id}/account-matches`.
- **D-20 Contacts.** New contact: ContactName = "salutation first last" trimmed, Title = job title, Phone = mobile ?? phone, Email; never primary unless the account has no contact. Same person at two companies = two rows (BR-23, already how SupplierContacts work).
- **D-21 Rich text.** Activity description is HTML from a small contenteditable editor (bold, italic, underline, lists); the server keeps only `p br div span b strong i em u ul ol li` with no attributes (script/style dropped with their content) — `CrmHtml.Sanitize`. Max 1 MB.
- **D-22 Frontend.** Angular, SMS Flow kit. Menu: top-level "CRM" (Leads, Opportunities, Activities, Campaigns) + "CRM Settings" pages (Lead sources, Pipeline stages, Sales teams, API keys) under Settings › Sales & Fulfilment. Routes `/portal/pages/crm/leads`, `/leads/:uuid`, `/opportunities`, `/opportunities/:uuid`, `/activities`, `/campaigns`, `/crm-settings/*`. Lead list ⇄ kanban toggle, detail with timeline + cross-references, conversion dialog, opportunity detail with pipeline bar + linked documents, activity form dialog, campaign list/form. Guards: permission + MODULE_CRM feature.

## Residuals (expected)
- R-1 Timeline PDF export not built (spec Phase 3).
- R-2 Lead assignment rules, scoring, widget, external sync, SLA — Addendum 42 ("Coming soon" features).

- R-4 Public API rate limit is per API process (in-memory window).
- R-5 Contact persons on inquiry/quotation/SO are still not stored (see the separate customer-contact proposal).
